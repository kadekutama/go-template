## Objective

Provide one shared Testcontainers lifecycle harness plus deterministic ledger fixtures so E07/E08/E10 integration suites never invent container management independently.

## Scope

### In Scope

- `test/testcontainers/{postgres,valkey,nats,unleash,minio,maildev,harness}.go`: one start/wait-ready/connection/terminate helper per dependency with pinned images and bounded startup contexts.
- `test/fixtures/{tenant,accounts,postings,workflows,statements}.go`: minimal ledger fixtures first with stable IDs/builders; extended fixtures additive.
- CI (reduced resources) + local debug profiles; per-test cleanup; repeatable runs without leaked containers.

### Out of Scope

- Feature integration suites themselves (E07-T06, E08-T06, E10-T06 consume; own their assertions).
- Production container topology (E17 owns compose/K8s manifests; this task only pins test images).
- Migration SQL content (E07-T01/T10 own versions; harness only boots PostgreSQL).

## Normative Inputs

- `tasks/epics/E07-persistence.md#E07-T09` for the backlog boundary.
- `SPEC.md §10.3` (Testcontainers for integration tests), `SPEC.md §12` (100% dockerized dependencies).
- `tasks/SDD.md §5` (shared harnesses separate from consuming suites).
- `scripts/test/integration.sh` (runs `go test ./test/integration/...`; exits 0 until suites land).

## Interfaces and Data

```go
// testcontainers.Harness{StartPostgres(ctx) (PostgresHandle, error); ...}
// PostgresHandle{ConnectionString() string; Terminate(ctx) error}
// fixtures.Tenant(id string) TenantFixture; fixtures.Accounts(...) [...]AccountFixture
// Stable IDs: "tnt-test-01", "acct-test-01", ... documented in package doc.
```

No wire/schema compatibility concerns; test-only APIs versioned by the module.

## Invariants and Failure Semantics

- Startup timeouts bounded (default 120s, CI 60s); failures return errors, never panic in helpers.
- Cleanup uses `t.Cleanup`; double-terminate is a no-op returning nil.
- Fixture builders are pure (no I/O, no randomness); determinism proven by test.
- Docker absence skips (never fails) container tests via `TB.Skip`.
