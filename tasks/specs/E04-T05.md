# Task Specification: E04-T05 — AML/KYC hooks + regulatory report definitions

**Task:** E04-T05
**Spec Status:** ready
**Author:** opencode-agent
**Reviewer:** repo-owner
**Last Updated:** 2026-09-14

## Objective

Ship pure transaction-screening hooks (ALLOW/REVIEW/BLOCK with reason codes) plus versioned regulatory report field definitions for 1099, FATCA, CRS, and call reports.

## Scope

### In Scope

- `internal/domain/service/aml_service.go`: `ScreenTransaction`, threshold/velocity/watchlist matrix.
- `internal/domain/repository/aml_provider.go`: `AMLProvider` screening port + `ReviewQueueEntry` shape.
- `internal/domain/service/regulatory_reports.go`: `ReportFields`, `ValidateReport`.

### Out of Scope

- Vendor screening calls, hold commit path, queue persistence (E10/E07); handlers/API/report rendering (E06/E11/E18).

## Normative Inputs

- `tasks/epics/E04-compliance.md#E04-T05` for the backlog boundary.
- `docs/fintech-ledger-features.md §4.1` (AML/KYC monitoring hooks; call reports, 1099, FATCA, CRS).
- `docs/user-journeys.md §5` (compliance review journey; holds via account Hold).
- `docs/ledger-core.md §2` (Hold changes available balance; not a posted fact).

## Requirements

| ID | Requirement | Priority |
|----|-------------|----------|
| E04-T05-R01 | Screening MUST evaluate amount thresholds, day-velocity (count + sum), and watchlist flag in that precedence and return exactly one of `ALLOW`, `REVIEW`, `BLOCK` with a stable reason code. | must |
| E04-T05-R02 | `BLOCK`/`REVIEW` decisions MUST carry reason codes mappable to the error table (`SCREENING_REASON_REQUIRED` otherwise). | must |
| E04-T05-R03 | `REVIEW` MUST produce a review-queue entry shape (tenant, account, amount, reason, rule version) suitable for hold placement via E02-T03 Hold. | must |
| E04-T05-R04 | Each report type (`CALL_REPORT`, `FORM_1099`, `FATCA`, `CRS`) MUST expose a non-empty versioned field list via `ReportDefinitionFor` with `Version == ReportDefinitionVersion` and a non-empty aggregation rule; empty/unknown types MUST fail (`REPORT_FIELDS_REQUIRED` / `REPORT_TYPE_UNKNOWN`). | must |
| E04-T05-R05 | `ValidateReport` MUST reject missing required fields and unknown report types without inventing jurisdiction field semantics. | must |
| E04-T05-R06 | New code MUST import only stdlib + `internal/domain/...`. | must |

## Executable Scenarios

| ID | Given | When | Then |
|----|-------|------|------|
| E04-T05-S01 | Threshold/velocity matrix rows | ScreenTransaction | ALLOW/REVIEW/BLOCK per matrix with reason codes |
| E04-T05-S02 | Watchlisted actor below thresholds | ScreenTransaction | BLOCK + `WATCHLIST_HIT` |
| E04-T05-S03 | Each of 4 report types | ReportFields | non-empty versioned list; ValidateReport passes on full field set, fails on missing field |
| E04-T05-S04 | Unknown report type | ReportFields/ValidateReport | `REPORT_TYPE_UNKNOWN` |

## Interfaces and Data

```go
// ScreeningDecision string: ALLOW, REVIEW, BLOCK
// ScreeningRequest{TenantID, AccountID string, AmountMinor int64, AssetCode string, DayCount int, DaySumMinor int64, Watchlisted bool, RuleVersion string}
// ScreeningPolicy{MaxAmountMinor int64, MaxDayCount int, MaxDaySumMinor int64, RuleVersion string}
// ScreenTransaction(req ScreeningRequest, policy ScreeningPolicy) (ScreeningDecision, string, error)
// ReviewQueueEntry{TenantID, AccountID, AmountMinor int64, AssetCode, ReasonCode, RuleVersion string}
// BuildReviewEntry(req ScreeningRequest, reasonCode string) (ReviewQueueEntry, error)
// ReportType string: CALL_REPORT, FORM_1099, FATCA, CRS
// ReportDefinition{Type, Version, RequiredFields, AggregationRule string}
// ReportDefinitionFor(t ReportType) (ReportDefinition, error); ReportFields(t ReportType) ([]string, error); ValidateReport(t ReportType, fields map[string]string) error
// port.AMLProvider interface { Screen(req ScreeningRequest) (ScreeningDecision, string, error) }
```

## Invariants and Failure Semantics

- Screening is pure and deterministic; same input → same decision. Stable codes: `SCREENING_REASON_REQUIRED`, `REPORT_FIELDS_REQUIRED`, `REPORT_TYPE_UNKNOWN`, `REPORT_FIELD_MISSING`, `WATCHLIST_HIT`.
- No PII or vendor payloads stored in domain results; only IDs + reason codes.
