## Objective

Make `testcontainers.StartNATS` return only after the isolated NATS container is
reachable through a real host-side NATS client handshake, eliminating the local
parallel-suite flake where `nats.Connect` fails with
`nats: no servers available for connection`.

## Scope

### In Scope

- Strengthen the shared NATS test helper's readiness contract.
- Wait for both the container log and the host-mapped client endpoint.
- Verify a real NATS handshake from the test process before returning.
- Add a regression assertion to the existing harness smoke suite.
- Keep the production NATS publisher and its fail-fast behavior unchanged.

### Out of Scope

- Any change to `internal/infrastructure/messaging/nats/**`.
- Any change to `test/integration/messaging/messaging_test.go`.
- Docker Compose ordering, healthcheck, or application startup retry behavior.
- Changes to `testcontainers-go` upstream.
- Changing the NATS image or production dependency versions.

## Interfaces and Data

No exported API changes. `StartNATS(t *testing.T) (*NATSHandle, error)` and
`NATSHandle.URL() string` keep their existing signatures. Readiness constants are
private to the `testcontainers` package. The existing log-only wait is replaced
with a combined container wait plus host-side NATS handshake.

## Invariants and Failure Semantics

- The startup context remains bounded by `Background()`.
- The readiness probe may retry only until its private deadline; no unbounded
  loop.
- A failed probe terminates the container through the existing handle lifecycle
  and returns an error wrapping the last observed connection failure.
- A successful probe connection is closed before the handle is returned.
- Probe retries use no production wrapper and do not alter publisher behavior.
- The helper remains test-only and is never imported by production code.

## Test Assertion Exception

`TestHarnessSmoke` adds one external assertion after `StartNATS` returns: it
opens and closes a NATS connection against `NATSHandle.URL()`. `StartNATS`
returns only `(*NATSHandle, error)`, so the helper's core contract—that callers
can immediately connect—cannot be observed through the returned values alone.
This is the only side-effect assertion for the helper, and it is explicitly
recorded as the packet exception for E09.3-T02-S01/S04.
