# Task Specification: E09-T04 — API keys (scoped, rotatable, rate-limited)

**Task:** E09-T04
**Spec Status:** ready
**Author:** muse-spark
**Reviewer:** kadekutama
**Last Updated:** 2026-09-23

## Objective

Deliver server-to-server API keys behind `port.APIKeyStore` with prefix + checksum format, Argon2id-hashed storage, scopes, dual-active rotation, and durable revocation.

## Scope

### In Scope

- `internal/infrastructure/auth/apikey/` package: `manager.go` (Create/Verify/Revoke), `hasher.go` (Argon2id + constant-time verify), store seam (in-memory default, Postgres binding later), rotation window, usage-metrics hook.
- `Module() fx.Option` exposing `port.APIKeyStore`.
- Unit tests (scope deny, rotation overlap, revocation, cancel).

### Out of Scope

- HTTP middleware mapping to 403/429 (E11 consumes), per-key rate-limit tiers enforcement beyond scope metadata (E08 limiter consumes).

## Normative Inputs

- `tasks/epics/E09-identity-security.md#E09-T04` for the backlog boundary.
- `SPEC.md §7.4` (scoped, rotatable API keys) and `docs/fintech-ledger-features.md §10`.
- `internal/application/port/apikey.go` (`APIKey`, `APIKeySecret`, `APIKeyStore` contract).

## Requirements

| ID | Requirement | Priority |
|----|-------------|----------|
| E09-T04-R01 | Key format MUST be `prefix.secret.checksum`; plaintext MUST appear only in the `Create` response and MUST never hit logs/traces. | must |
| E09-T04-R02 | Storage MUST hold Argon2id hashes; `Verify` MUST compare in constant time and MUST fail closed on unknown/expired/revoked keys. | must |
| E09-T04-R03 | Out-of-scope endpoint use MUST be detectable via scopes and MUST surface a forbidden error for the edge to map. | must |
| E09-T04-R04 | Rotation MUST keep the old key valid during the dual-active window and MUST invalidate it after. | must |
| E09-T04-R05 | Revocation MUST be durable (store delete) with best-effort cache invalidation hook. | must |
| E09-T04-R06 | The adapter MUST implement `port.APIKeyStore` exactly and MUST expose `Module() fx.Option`. | must |

## Executable Scenarios

| ID | Given | When | Then |
|----|-------|------|------|
| E09-T04-S01 | New key request | `Create` | `APIKeySecret` with one plaintext reveal; stored hash verifies |
| E09-T04-S02 | Out-of-scope plaintext | Scope check via stored scopes | Forbidden (caller maps to FORBIDDEN) |
| E09-T04-S03 | Rotated key within window | `Verify` old + new | Both pass; after window old fails |
| E09-T04-S04 | Revoked key | `Verify` | Fails closed |
| E09-T04-S05 | Canceled context | `Create`/`Verify` | Context error |

## Invariants and Failure Semantics

- Secret shown exactly once; redacted from logs/traces; strong reads/writes per port docs.
- Revoke is idempotent; unknown IDs fail closed without existence oracle beyond the error code.

**Amendment 2026-09-23 (durable-boundary review, ADR-020):** Records live in
PostgreSQL `api_keys` (`20260923000007`, prefix unique index, RLS) via GORM —
no maps, no mutex. Hashing uses Argon2id with `hash`/`salt` BYTEA columns +
`version` tag (no PHC string is ever parsed; rationale in ADR-020). Rotation
window via `rotates_at` column.
**Amendment 2026-09-23 (review round 2):** KDF cost via `HasherParams`
(defaults RFC 9106 `t=3/m=64MiB/p=4`; validated ranges; rotate after any
change). IDs are database-minted (`default:uuidv7()`, E06-T15 — the adapter
never pre-mints).
**Amendment 2026-09-25 (review round 3, Antigravity Agent):** Upgraded `newSecret()` to 256-bit
entropy (32 cryptographically secure random bytes). Integrated `postgres.WithinTenantTx` for
`Create`, `Revoke`, and `Rotate` mutations; eliminated transactions on read-only queries.

**Amendment 2026-10-01 (GLM review fix round, CR-001/CR-008/CR-009):** `Verify`
now runs lookup, validity, hash verification, and the transparent re-hash upgrade
inside a single `postgres.WithinTenantTx` scoped to the tenant parsed from the
plaintext hint (RLS GUC set on reads — CR-001); re-hash/upgrade failures abort
verification instead of degrading silently (CR-009). `Rotate` mints the successor
and stamps `rotates_at` in one tenant-scoped transaction (CR-008); `NewManager`
rejects non-positive `RotationWindow` at construction (no 1h silent default).
Rollback: restore bare reads, two-step rotate, and the window fallback.
