## Objective

Enforce hard tenant boundaries in PostgreSQL: RLS policies per the E05-T03 matrix plus mandatory tenant context on every repository call.

## Scope

### In Scope

- `versions/000004_rls_policies.up/down.sql`: enable RLS on ledger-core + workflow tables, per-table policies keyed on `current_setting('app.current_tenant')`, service-role bypass for migrations.
- `postgres/rls/tenant.go`: tenant context helper (`WithTenant`, `TenantFromContext`), `SET LOCAL app.current_tenant` executor.
- Repository wiring: all adapters resolve tenant from context-or-argument and fail closed when missing.

### Out of Scope

- The E05-T03 isolation contract itself (already accepted; this task enforces it).
- Pool sizing (E07-T01 owns), read routing (E07-T07), residency (E07-T08).
- Application-level authz (Casbin in E09; RLS is defense-in-depth, not the only boundary).

## Normative Inputs

## Invariants and Failure Semantics

- Fail-closed everywhere: no tenant ⇒ error, never unbounded scan.
- Context/argument disagreement ⇒ error (prevents confused-deputy writes).
- `SET LOCAL` scopes to the transaction; pool reuse cannot leak tenants.
- Down migration disables RLS without dropping user data.

## Change Surface

**Owns:** `migration/versions/000004_*.sql`, `postgres/rls/*.go` + tests.

**Must Not Touch:** ledger-core logic, outbox relay, seed/backup, statuses outside E07-T02, Git remotes.

## Amendment (audit 2026-09-16)

- `000004_rls_policies.up.sql` applies `FORCE ROW LEVEL SECURITY` across all 18 tables so that table owners are also subject to RLS, while superusers and roles explicitly granted `BYPASSRLS` bypass RLS.
- `scopeTenant` in `internal/infrastructure/database/postgres/repositories/scope.go` explicitly enforces `rls.ResolveTenant(ctx, tenant)` to prevent confused-deputy bypass between caller context and query arguments.
- `TestAdversarialRLS` verifies tenant isolation under an application role `app_user` (`NOSUPERUSER NOBYPASSRLS`) via `SET LOCAL ROLE app_user` and confirms service-role bypass without `app_user` per `E07-T02-R02`.
