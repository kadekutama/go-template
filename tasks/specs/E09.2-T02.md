## Objective

Standardize dependency-injection testing on `fx.ValidateApp` (static graph validation without side effects) and `go.uber.org/fx/fxtest` (`fxtest.New`, `RequireStart`, `RequireStop`) across all infrastructure `module.go` packages and `internal/shared/di/`, eliminating raw `fx.New` usage in unit tests (`internal/infrastructure/coordination/etcd/etcd_test.go`).

## Scope

### In Scope

- Refactor `internal/infrastructure/coordination/etcd/etcd_test.go` (`TestEtcdModule` and `TestEtcdModuleDrainsClient`) to replace raw `fx.New(...)` with `fx.ValidateApp(...)` and `fxtest.New(t, ...)`.
- Create table-driven `module_test.go` unit test suites for all 9 infrastructure packages with `module.go` that currently lack one:
  - `internal/infrastructure/audit/module_test.go`
  - `internal/infrastructure/crypto/module_test.go`
  - `internal/infrastructure/featureflag/module_test.go`
  - `internal/infrastructure/secrets/openbao/module_test.go`
  - `internal/infrastructure/cache/hybrid/module_test.go`
  - `internal/infrastructure/auth/oauth2/module_test.go`
  - `internal/infrastructure/auth/apikey/module_test.go`
  - `internal/infrastructure/auth/jwt/module_test.go`
  - `internal/infrastructure/auth/rbac/module_test.go`
- Expand `internal/shared/di/di_test.go` to verify composite module graphs via `fx.ValidateApp` and lifecycle hook ordering via `fxtest.New`.

### Out of Scope

- Changing production `fx.Module` provider signatures unless a genuine cycle or missing dependency bug is uncovered by `fx.ValidateApp`.
- `samber/lo` (`E09.2-T01`), `nilaway` (`E09.2-T03`), and `pyroscope-go` (`E09.2-T04`).

## Implementation Notes

- **C01 — hybrid suite name collision (2026-10-20):** `internal/infrastructure/cache/hybrid/engine_test.go` already declares `TestModule` in package `hybrid_test`. The new `module_test.go` therefore names its suite `TestModuleGraph`; R02 coverage (valid graph plus missing-dependency rejection) is unchanged.
- **C02 — lifecycle side-effect assertions (2026-10-20):** fx lifecycle hooks return no values, so R03's "one assertion per returned value" cannot observe ordering through a single return tuple. `TestCompositeLifecycle` asserts one aggregate `lifecycleTrace` value for start/stop order, and `TestEtcdModuleDrainsClient` asserts the single `error` returned by `Client.Health` after teardown. Both follow the existing `fxtest` precedent in `internal/infrastructure/httpclient/client_test.go`.
