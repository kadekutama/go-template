# Task Specification: E09-T07 — Audit logger (append-only, hash-chained, signed)

**Task:** E09-T07
**Spec Status:** ready

**Last Updated:** 2026-09-23

## Objective

Deliver the tamper-evident audit trail behind `port.AuditLogger` with per-tenant hash chains, HMAC-SHA256 entries, periodic signed checkpoints, and Loki + WORM export seams.

## Scope

### In Scope

- `internal/infrastructure/audit/` package: `logger.go` (Record), `chain.go` (append-only + per-tenant hash chain + HMAC), `exporter.go` (Loki seam + immutable cold-store seam + signed Merkle-root checkpoint), `Module() fx.Option`.
- Store seam (in-memory default; Postgres binding later); every E04-T02 approval and E04-T04 erasure shapes recordable.
- Unit tests (tamper/delete/reorder detection vs checkpoint, hook coverage, cancel).

### Out of Scope

- E04 approval/erasure workflows themselves (they call this port), Loki/c object-store provisioning (E15/E17 consume the exporter).

## Normative Inputs

- `tasks/epics/E09-identity-security.md#E09-T07` for the backlog boundary.
- `SPEC.md §14` (tamper-evident trail, 7y retention note) and `docs/data-flow.md §7`.
- `internal/application/port/audit.go` (`AuditEntry`, `AuditLogger` contract).

## Requirements

| ID | Requirement | Priority |

**Amendment 2026-09-23 (durable-boundary review, ADR-020):** The chain lives in
PostgreSQL `audit_entries` (`20260923000008`, `PRIMARY KEY (tenant_id, seq)`,
RLS); appends serialize with `pg_advisory_xact_lock` per tenant inside the
insert transaction (no app mutex). Framing uses `strings`/`strconv` stdlib
(hand helpers deleted). Verify/Checkpoint are lock-free reads.
**Amendment 2026-09-23 (review round 2):** `RecordTx(ctx, tx, entry)` added so
command handlers commit audit facts inside the UnitOfWork callback (E07
`AppendTx` pattern); `Record` keeps the standalone path. Validation runs
before any SQL in both paths (a refactor regression that dialed before
validating was caught by the no-Docker unit suite and fixed).
**Amendment 2026-09-25 (review round 3, Antigravity Agent):** Replaced `pg_advisory_xact_lock`
with row-level locking on dedicated `audit_heads` table (`SELECT last_seq, last_hash FROM audit_heads WHERE tenant_id = ? FOR UPDATE`)
inside `postgres.WithinTenantTx`. Sharded on Citus by `tenant_id`, eliminating 32-bit hash
collisions and table scans. Checkpoint calculation updated to pairwise binary Merkle tree root
(RFC 6962). Implemented missing `Verify(ctx, tenant)` on `*Logger`.

**Amendment 2026-10-01 (GLM review fix round, CR-002/CR-003):** `prepare`
normalizes timestamps to microsecond precision before hashing (PostgreSQL
timestamptz stores microseconds; unverified nanoseconds false-alarmed as
tampering). `VerifyCheckpoint` verifies the attested prefix `chain[:root.Seq]`
(truncation still fails closed); post-checkpoint appends no longer invalidate
old checkpoints. First-append head creation is idempotent via
`INSERT ... ON CONFLICT DO NOTHING` + re-read under lock (concurrent first
appends serialize without application retry). Rollback: restore full-precision
hashing and length-equality checkpoint semantics.
