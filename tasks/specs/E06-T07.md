## Objective

Orchestrate long-running money flows with compensation: idempotent steps, per-step timeouts/retry, persisted saga records for crash resume — with a saga test for every money-flow §10 failure row.

## Scope

### In Scope

- `internal/application/workflow/{saga,compensate,transfer,refund,payout_settlement,reconciliation,period_close,batch}.go` (+ `saga.go` runner core alongside the epic's six files + `compensate.go`): `SagaRecord`/`SagaStore` (consumer-owned, E07-T10 implements), generic `Runner` (explicit saga IDs, skip-completed resume, reverse-order compensation, per-step timeout via ctx), six kind builders over injected actions.
- Tests: crash-resume (one effect per step key), compensation order, duplicate-start single effect, and one test per §10 row (DB crash, Valkey down, NATS down, processor timeout, FX stale, recon break, duplicate submit, auth expiry, over-capture, dispute lost).

### Out of Scope

- Worker/cron execution (E14 drives `Resume`), persistence schema (E07-T10 implements `SagaStore`), provider retry policies beyond step attempts (E10), NATS/Valkey adapters (E08).

## Requirements

| ID | Requirement | Priority |
|----|-------------|----------|
| E06-T07-R01 | The runner MUST persist step states, skip completed steps on resume, and execute each step effect once per step key. | must |
| E06-T07-R02 | Step failure past `MaxAttempts` MUST compensate completed steps in reverse order; compensation failure MUST park the saga FAILED with the error recorded. | must |
| E06-T07-R03 | Per-step `Timeout` MUST bound attempts via ctx; duplicate `Start` with the same saga ID MUST return the stored record without re-executing. | must |
| E06-T07-R04 | Six kind builders MUST encode the §2/§5/§6/§10 flows (transfer, refund, payout-settlement, reconciliation, period-close, batch) with kind-appropriate compensations (none where no money moves). | must |
| E06-T07-R05 | Every money-flow §10 row MUST have a saga test mapping failure → detection → money-safe recovery. | must |

## Invariants and Failure Semantics

- Actions are idempotent on sagaID:step keys (runner documents; fakes prove); the runner never re-runs COMPLETED steps.
- Compensation never writes partial ledger state (payout-settlement failure → hold + notify only).
- Timeouts are enforced per attempt; retries reuse step keys; unknown outcomes resolve by resume, never blind restart.
