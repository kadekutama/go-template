## Audit Finding Fixed: DLQ replay was swallowed (2026-09-19, muse-spark)

- **Defect:** on DLQ routing the framework returned nil (ack) without releasing the inbox receipt. Per `docs/domain-events.md §5.2` the receipt represents a committed effect; the handler never committed one, so the retained claim would make a DLQ replay after an operator fix a silent duplicate ack — the poison could never be reprocessed.
- **Fix:** `routeFailure` now releases the receipt after recording to the DLQ (joined error if release fails, returning to the caller for redelivery) and returns nil only when the claim is freed. With a nil DLQ sink, exhaustion returns the handler error so the broker policy decides.
- **Tests:** `TestFrameworkRedeliveryReleasesClaim/poison_reaches_dlq_after_max_delivers` now proves a DLQ replay re-runs the handler; new `exhausted without dlq keeps redelivering` case covers the nil-sink policy.
- Re-verified: `go test ./internal/infrastructure/messaging/... -count=3` green; `make lint` 0 issues.
