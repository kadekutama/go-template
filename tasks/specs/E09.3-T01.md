## Interfaces and Data

```go
// internal/infrastructure/logging
type Config struct {
    Level       string
    Output      string // stdout | file | both
    FilePath    string
    MaxSizeMB   int
    MaxBackups  int
    MaxAgeDays  int
    Compress    bool
}

func (c Config) Validate() error
func (c Config) Normalized() Config
func New(w io.Writer, cfg Config) log.Logger
func NewFromConfig(cfg Config) (log.Logger, error)
```

Environment contract:

```text
APP_ENV=local|staging|production              (default local)
APP_LOG_LEVEL or APP_OBSERVABILITY__LOG_LEVEL (required; existing contract)
APP_LOG_OUTPUT or APP_OBSERVABILITY__LOG_OUTPUT = stdout|file|both
APP_LOG_FILE or APP_OBSERVABILITY__LOG_FILE
APP_LOG_MAX_SIZE_MB or APP_OBSERVABILITY__LOG_MAX_SIZE_MB
APP_LOG_MAX_BACKUPS or APP_OBSERVABILITY__LOG_MAX_BACKUPS
APP_LOG_MAX_AGE_DAYS or APP_OBSERVABILITY__LOG_MAX_AGE_DAYS
APP_LOG_COMPRESS or APP_OBSERVABILITY__LOG_COMPRESS
```

`APP_APP__ENV` is accepted as the koanf-style fallback for `APP_ENV`. Output
defaults to `stdout` when no environment is supplied, and to `file` only for an
explicit `staging`/`production` environment. A file-mode server must provide a
path; the sample deployment uses `/var/log/go-template/app.log`.

## Invariants and Failure Semantics

- The logger is an infrastructure concern; domain/application imports stay
  unchanged.
- Log levels and output modes are validated at startup; invalid values fail the
  process before serving.
- Logging a record never returns an error to the caller (existing port
  contract); writer creation and configuration failures happen at construction.
- Rotation is size-first with bounded backups and age; `MaxSizeMB` is positive,
  `MaxBackups` and `MaxAgeDays` are non-negative.
- File mode is append-only JSON lines. The log processor consumes the file; the
  application does not buffer unbounded records in memory or make network calls
  from the logger.
- `io.Discard` is not a logging sink. The two HTTP response-body drains remain
  because they do not hide terminal/file output.
- No credentials, tokens, or log payloads are added to configuration or tests.

## Test Convention Exception

The file-output scenarios require observing bytes after a logger writes them.
`NewFromConfig` returns only `(log.Logger, error)`; the file content is an
essential side effect that cannot be observed through that return tuple. For
S07 only, the test may read the temporary file after logging and assert the JSON
line. Rotation settings may be proven by inspecting the constructed
`lumberjack.Logger` configuration in the same exception, because a real 1 MB+
rotation write would make the unit suite slow and timing-sensitive. Every other
test asserts each returned value exactly once inside its table subtest.
