# Task Specification: E07.1-T02 — Multi-Node Citus + Patroni + etcd HA cluster topology

## Objective

Provide a reproducible Docker Compose topology for Citus 14.0 sharded PostgreSQL with Patroni v4.1.5 HA supervised by a 3-node etcd v3.7.0 DCS, so multi-node sharding and failover behavior can be exercised locally and in CI without touching application code.

## Scope

### In Scope

- `deployments/docker/docker-compose.citus-patroni.yml`: 3-node etcd cluster, Citus coordinator (1 primary + 1 standby via Patroni), 2 Citus worker shards (each 1 primary + 1 standby via Patroni).
- `deployments/patroni/citus-coordinator.yml` and `deployments/patroni/citus-worker.yml`: Patroni DCS, replication, and Citus extension bootstrap configuration.
- Service endpoints routing application traffic to the active Citus coordinator primary.
- Compose-level healthchecks and worker registration verification guidance.

### Out of Scope

- Migration file contents and Goose runner behavior (owned by E07.1-T01).
- Kubernetes CloudNativePG manifests (owned by E07.1-T03).
- etcd client adapter code (owned by E07.1-T04).
- Go integration test suite (owned by E07.1-T05).

## Requirements

| ID | Requirement | Priority |
|----|-------------|----------|
| E07.1-T02-R01 | The compose file MUST define a 3-node etcd cluster (etcd1, etcd2, etcd3) with Raft consensus, persistent volumes, and healthchecks. | must |
| E07.1-T02-R02 | The compose file MUST define a Citus coordinator tier (1 primary + 1 standby) managed by Patroni v4.1.5 with synchronous replication for RPO=0. | must |
| E07.1-T02-R03 | The compose file MUST define 2 Citus worker shards, each with 1 primary + 1 standby managed by Patroni. | must |
| E07.1-T02-R04 | Patroni configs MUST point at the etcd DCS, declare Citus extension bootstrap, and expose REST health endpoints used by compose healthchecks. The Patroni supervisor MUST ship in the same image as Citus (`deployments/patroni/Dockerfile`). | must |
| E07.1-T02-R05 | Application traffic MUST route through the coordinator primary endpoint; standby endpoints MUST NOT accept writes. | must |

## Interfaces and Data

- Compose services: `etcd1/2/3` (ports 2379/2380), `citus-coordinator`, `citus-coordinator-standby`, `citus-worker1`, `citus-worker1-standby`, `citus-worker2`, `citus-worker2-standby`.
- Patroni REST: port 8008 per Postgres node for role and health probes.
- Connection endpoint: coordinator primary `postgres://ledger:ledger_pw@citus-coordinator:5432/ledger`.
- No application Go interfaces change in this task.

## Invariants and Failure Semantics

- **Split-brain safety**: Patroni supervised by etcd Raft quorum; single primary per tier at any time.
- **Zero data loss posture**: coordinator and workers use synchronous replication (`synchronous_commit = on`, `num_sync >= 1`).
- **Static validation only**: this task proves topology definition and config validity; live failover timing is proven in E07.1-T05.
