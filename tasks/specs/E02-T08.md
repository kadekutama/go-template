## Objective

Ship small consumer-owned repository ports for every E02 aggregate with documented consistency expectations, tenant scoping, and no generic Save/Delete — plus an in-memory fake proving implementability (mock generation runs in E06).

## Scope

### In Scope

- `internal/domain/repository/{ledger,account,posting,entry,hold,journal,period}.go`:
  - `LedgerRepository`: Create, FindByID, ListByTenant.
  - `AccountRepository`: Create, FindByID, FindByTenant (cursor + limit), UpdateMetadata, UpdateStatus — all with expected-version optimistic locking on writes.
  - `PostingRepository`: atomic `Commit` (posting + entries as one unit), FindByID, FindByExternalReference, FindByAccount (cursor + limit).
  - `EntryReader`: FindByPosting, FindByAccount (cursor + limit). No entry write port — entries persist only via `PostingRepository.Commit`.
  - `HoldRepository`: Create, FindByID, FindActiveByAccount, Update (state + expected version).
  - `JournalRepository`: Create, FindByID, FindByPeriod.
  - `PeriodRepository`: Create, FindByID, FindOpen, FindByDate.
- Every method: `ctx` first, tenant-scoped, `(value, error)` returns, and a doc comment stating strong-read vs cacheable consistency.
- `ports_test.go`: in-memory fakes for Account + Posting ports proving interface satisfaction, round-trips, and version-conflict behavior.

### Out of Scope

- Durable idempotency ports (E06 application-owned, E07 implemented).
- Checkpoint/outbox/inbox rows (E07 transaction internals, surfaced via `Commit` atomicity there).
- Mockery generation (E06 `make generate-mocks` consumes these ports).
- Any implementation (E07 adapters).

## Interfaces and Data

- Seven port interfaces as listed in Scope; cursor pagination is `(cursor string, limit int) → (page, nextCursor string, error)` with opaque cursors owned by the adapter.
- `Commit` is the single atomic posting write; adapters extend atomicity to checkpoints/outbox in E07 without changing this signature.
- No wire/migration/config change.

## Invariants and Failure Semantics

- Tenant isolation is a port contract: adapters MUST NOT return cross-tenant rows (adversarial test in E07).
- Version conflicts are retryable caller-side errors, never panics.
- `FindByTenant`/`FindByAccount` pages are point-in-time and carry opaque cursors; strong reads use `FindByID`.
