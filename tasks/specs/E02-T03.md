## Objective

Ship the Ledger and Account aggregates with classification, hierarchy, metadata versioning, and lifecycle transitions emitting the E02-T06 catalog events — with no mutable balance field and no deposit/withdraw behavior.

## Scope

### In Scope

- `internal/domain/valueobject/account_type.go`: `Direction` (DEBIT/CREDIT), `AccountClass` (ASSET/LIABILITY/EQUITY/REVENUE/EXPENSE), `AccountStatus` (ACTIVE/FROZEN/CLOSED), `NormalSide()` per `ledger-core.md §5`, strict `Parse*` constructors.
- `internal/domain/entity/errors.go`: shared coded `Error{Code,Message}` (no external deps).
- `internal/domain/entity/account.go`: `Ledger` (ID, TenantID, name, base asset, chart version) + `NewLedger`; `AccountData` persistence record (exported fields, structural `Validate()`; invariants enforced at the aggregate boundary).
- `internal/domain/aggregate/account.go`: `Account` aggregate (unexported state, `Version` optimistic locking, uncommitted-event buffer) with `OpenAccount`, `Freeze`, `Unfreeze`, `Close`, `Reparent`, `UpdateDetails`; emits `account.created/frozen/unfrozen/closed/updated.v1`.
- Lifecycle + normal-side + no-balance reflection + emission-order tests.

### Out of Scope

- Balances/projections (postings/checkpoints own them; E07 persists).
- Posting acceptance against frozen/closed accounts (E02-T04/T07 enforce `AccountActive` on the posting path).
- Deposit/Withdraw/balance setters/microdeposit verification (explicitly forbidden).
- External bank/card instruments (separate workflow entities, E03/E05).

## Executable Scenarios

| ID | Given | When | Then |
|----|-------|------|------|
| E02-T03-S01 | Valid open params | `OpenAccount` | ACTIVE account, Version 1, one `account.created.v1` with matching IDs. |

| E02-T03-S03 | FROZEN account | Second `Freeze` | `ACCOUNT_ALREADY_FROZEN`; no event, no version bump. |

| E02-T03-S07 | Reflection over aggregate + record | Balance/deposit search | No balance field, no Deposit/Withdraw methods. |
| E02-T03-S08 | Missing tenant/ledger/asset/name/number | `OpenAccount` | Coded validation error; no event. |

## Interfaces and Data

```go
// valueobject: Direction, AccountClass, AccountStatus (+ Parse + NormalSide)
// entity: Ledger + NewLedger; AccountData{ID,TenantID,LedgerID,ParentID *AccountID,
//   Number,Name,Class,AssetCode,Status,Purpose,Metadata,Version,CreatedAt,UpdatedAt} + Validate()
// entity: Error{Code,Message} + NewError
// aggregate: Account{data AccountData, events []event.DomainEvent}
//   OpenAccount(Ledger-ish params) (Account, error); Freeze/Unfreeze/Close/Reparent/UpdateDetails(...)
//   Record() AccountData (copy); UncommittedEvents() []event.DomainEvent; ClearEvents()
```

- Repos persist `AccountData` (T08); events drain to the outbox path (E07).
- No wire/migration/config change.

## Invariants and Failure Semantics

- CLOSED is terminal; FROZEN blocks posting-side use via `AccountActive` (T04/T07), not via aggregate mutation errors alone.
- Version starts at 1 and increments exactly once per successful mutation.
- Errors carry stable UPPER_SNAKE codes for spec/application mapping; panics forbidden.
- `ParentID` nil = root; reparenting to self errors.
