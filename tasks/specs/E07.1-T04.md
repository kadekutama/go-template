## Objective

Deliver the production infrastructure adapter for etcd v3.7.0 (`go.etcd.io/etcd/client/v3`) providing sub-millisecond HTTP/2 gRPC streaming configuration watchers and single-writer background worker leader election via Raft consensus leases per ADR-017.

## Scope

### In Scope

- `internal/infrastructure/coordination/etcd/client.go`: `Client` wrapping `clientv3.Client` with connection lifecycle management, healthcheck ping, and graceful shutdown.
- `internal/infrastructure/coordination/etcd/watcher.go`: `Watcher` providing persistent gRPC streaming watchers over key prefixes (e.g., `/config/tenants/`, `/feature-flags/`) updating thread-safe in-memory cache without polling.
- `internal/infrastructure/coordination/etcd/election.go`: `Election` wrapping `concurrency.NewElection` and session leases for single-writer saga coordination (reconciliation, period close).
- `internal/infrastructure/coordination/etcd/module.go`: fx module registering etcd client, watcher, and election dependencies.
- Unit and integration tests using Testcontainers or mock etcd client verifying stream updates and lease expiry failover.

### Out of Scope

- Multi-node etcd cluster deployment in Docker Compose (owned by E07.1-T02).
- Concrete cron and consumer workers campaign calls (owned by E14-T01).

## Requirements

| ID | Requirement | Priority |
|----|-------------|----------|
| E07.1-T04-R01 | The adapter MUST initialize `clientv3.Client` using endpoints and credentials from infrastructure configuration with auto-reconnect backoff. | must |
| E07.1-T04-R02 | `Watcher` MUST maintain a persistent gRPC watch stream over configured key prefixes and emit change notifications with sub-10ms latency. | must |
| E07.1-T04-R03 | `Election` MUST implement `Campaign(ctx, candidateID)` and `Resign(ctx)` using etcd leases (`concurrency.NewSession`) with configurable TTL (default 5s). | must |
| E07.1-T04-R04 | On ungraceful process termination or lease expiration, the election lock MUST release automatically allowing standby candidate takeover. | must |
| E07.1-T04-R05 | The adapter MUST register an `fx.Module` providing `Coordinator` dependencies cleanly to the application container. | must |

## Executable Scenarios

| ID | Given | When | Then |
|----|-------|------|------|
| E07.1-T04-S01 | Running etcd cluster and active watcher on `/config/` | Key `/config/fee_schedule` is put or updated | Watcher callback receives new value within 10ms without polling. |
| E07.1-T04-S02 | Two candidate instances A and B campaigning for same election key | Both call `Campaign(ctx)` simultaneously | Exactly one instance (A) acquires leadership; B blocks or yields standby status. |
| E07.1-T04-S03 | Active leader A holds lease with 5s TTL | Leader A disconnects without calling `Resign` | Session lease expires after 5s; standby B immediately acquires leadership. |
| E07.1-T04-S04 | Active leader A completes job normally | Leader A calls `Resign(ctx)` | Lease is voluntarily revoked; election yields immediately to next queued candidate. |
| E07.1-T04-S05 | Temporary network partition to etcd cluster | Connection dropped and restored within lease keepalive | Client reconnects automatically without losing leader session. |

## Invariants and Failure Semantics

- **Mutual Exclusion**: At most one leader holds the election lock for any election key at any given point in physical time.
- **Fail-Safe Lease Expiration**: Partitions or killed worker processes forfeit leadership after TTL expiry without manual intervention.
- **Zero Polling**: Dynamic configuration streaming must not use polling loops or timer tickers.
