## Objective

Deliver tenant webhook fanout for all `api-contracts §10` types with HMAC signatures, retry schedule, per-endpoint breaking, and isolation across endpoints.

## Scope

### In Scope

- `internal/infrastructure/webhook/signer.go`: HMAC over `timestamp + "." + raw_body`, `v1=` values, tolerance, key ID, constant-time verify, dual-secret rotation.
- `internal/infrastructure/webhook/registry.go`: endpoint CRUD backing store (URL, events[], secret, retry policy) via `WebhookSubscriptionRepository` shape.
- `internal/infrastructure/webhook/retry.go`: 1m→5m→15m→1h→6h→24h→48h (7 attempts, ~72h), then DLQ.
- `internal/infrastructure/messaging/redpanda/consumer/webhook_dispatcher.go`: delivery group consumer implementing `port.WebhookDispatcher` + `port.MessageConsumer` handler.
- Isolation: one failing endpoint never blocks others.

### Out of Scope

- Webhook-mgmt REST API (E11-T07), broker topology (E08-T03), ledger posting (never gated on dispatch).

## Normative Inputs

- `tasks/epics/E08-cache-messaging.md#E08-T05`.
- `docs/api-contracts.md §10–§11` (24+ types, signature example) and `docs/user-journeys.md §2.1` (delivery flow).
- `tasks/specs/E06-T12.md` (`WebhookDispatcher{Dispatch}` contract).

## Requirements

| ID | Requirement | Priority |
|----|-------------|----------|
| E08-T05-R01 | Signer MUST HMAC `timestamp + "." + raw_body` with `v1=` values, tolerance window, key ID, constant-time compare, and dual-secret overlap; `Verify` MUST accept multiple comma-separated `v1=` values per api-contracts §11, and the exact scheme MUST be pinned by an independent known-vector test. | must |
| E08-T05-R02 | Registry MUST validate endpoints (ID/tenant/URL/events/secret) with `go-playground/validator` after trimming, MUST scope reads by tenant, and secrets MUST never appear in logs/errors. | must |
| E08-T05-R03 | Retry MUST follow 1m→5m→15m→1h→6h→24h→48h then DLQ via a configurable `RetryPolicy` (default 7 retries / `MaxAttempts` 8): each `Dispatch` call makes one attempt per endpoint, failures release the delivery receipt and return `*RetryableError` with the `NextDelay` for the E14 worker to re-queue, and the `MaxAttempts`-th consecutive failure records to DLQ and parks the endpoint breaker until operator reset. Waiting/re-queueing belong to E14. | must |
| E08-T05-R04 | Dispatch MUST be idempotent per delivery identity (SHA-256 over exact payload bytes, sent as `X-Ledger-Event-ID`) and MUST isolate endpoints (one failure never blocks others). | must |
| E08-T05-R06 | Delivery headers MUST be exactly `X-Ledger-Signature` / `X-Ledger-Timestamp` / `X-Ledger-Event-ID` / `X-Ledger-Key-ID` (`k1`) per api-contracts §11. | must |
| E08-T05-R05 | Payloads MUST match `api-contracts §10` shapes byte-for-byte (sign what is sent). | must |

## Executable Scenarios

| ID | Given | When | Then |
|----|-------|------|------|
| E08-T05-S01 | Valid payload + secret | Sign then verify | Pass; tampered body/timestamp fails |
| E08-T05-S02 | Rotating secrets (old+new) | Verify during overlap, incl. combined `v1=old,v1=new` header | Overlap passes; after window only new passes |
| E08-T05-S03 | Failing endpoint + healthy endpoint | Dispatch batch | Healthy delivered; failing returns `RetryableError`, batch continues |
| E08-T05-S04 | Duplicate event ID | Dispatch twice | Second is deduped (single delivery attempt recorded) |
| E08-T05-S05 | Endpoint failing 8 consecutive dispatches (initial + 7 retries) | 8th `Dispatch` | Records to DLQ with attempt count, parks breaker, releases receipt, returns nil; 9th call skips |
| E08-T05-S06 | Delivered batch | Inspect headers | Exactly `X-Ledger-Signature/Timestamp/Event-ID/Key-ID`, no legacy names |
| E08-T05-S07 | Independent recomputation of the §11 algorithm | Compare with `Signer.Sign` | Byte-identical `v1=<hex>` and `Verify` accepts it |
| E08-T05-S08 | Invalid endpoint (blank ID/tenant, non-http URL, no events, blank secret) | `Registry.Upsert` | Joined validator violations, nothing stored |

## Invariants and Failure Semantics

- At-least-once per message; receivers dedupe on event ID in payload.
- Dispatcher state never gates ledger writes; shutdown drains in-flight deliveries.
- Secrets redacted; replay outside tolerance rejected.
