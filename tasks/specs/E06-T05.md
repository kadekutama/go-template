## Objective

Back the ops/compliance surface: reconciliation runs with break resolve/acknowledge, period open/close/reopen with complete failure reporting, all 10 named report types with delivery, and screening/regulatory workflows — over the E04 domain services.

## Scope

### In Scope

- `internal/application/command/{reconciliation,period,report,compliance}.go`: run trigger + `ExecuteRun` matching, resolve/ack with SoD passthrough, period lifecycle (close returns ALL failures), 10-type report generation with signed-URL delivery, screening record + regulatory CSV export; consumer-owned stores (E07-T10 implements).
- `internal/application/query/{reconciliation,period,report,compliance}.go`: delegating readers.
- Tests: 10 report types parameterized, period-close multi-failure, SoD passthrough, replay/conflict, auth denial.

### Out of Scope

- Persistence schema (E07-T10), full renderer depth (summaries backed by real posting reads; projection-powered renderers later), provider screening calls (E10), cron execution (E14 drives `ExecuteRun`), extended reporting (E06-T09), sagas (E06-T07).

## Invariants and Failure Semantics

- Domain owns matching, transitions, close gates, and field defs; handlers book state around them.
- Catalog facts only (run.started/completed, break.found/resolved/acknowledged, period.opened/closed/reopened, report.generated); screening decisions are queryable state.
- Unknown commit outcomes resolve via identical resubmission, never blind retry.
