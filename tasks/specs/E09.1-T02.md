# Task Specification: E09.1-T02 — gocron-ui secure internal ops surface

**Task:** E09.1-T02

## Objective

Mount pinned gocron-ui v0.3.0 as a disabled-by-default, internal-only, read-only dashboard. Authentication and routing must contain upstream unauthenticated and cross-origin defaults; no scheduler mutation is exposed.

## Scope

### In Scope

- `go.mod` / `go.sum`: exact `github.com/go-co-op/gocron-ui v0.3.0` pin (Go 1.24 module; compatible with repository Go 1.27.1). Production import retains the pin, so no blank-import anchor is needed. Its own `go.mod` requires gocron/v2 v2.19.0 plus `gorilla/mux`, `gorilla/websocket`, `rs/cors`, and `google/uuid` as new indirect pins; Go MVS must keep the direct `gocron/v2 v2.22.0` requirement from E09.1-T01 (do not let the upstream v2.19.0 lower it), and no module downgrades are allowed.
- `SPEC.md §2`: exact gocron-ui module pin alongside the scheduler pin; run `go mod tidy` and verify via `go list -m all | grep go-co-op` that gocron-ui's indirect gocron/v2 requirement is not the effective version used at build time, since a direct requirement exists.
- `internal/infrastructure/cronui/handler.go`: construct the pinned upstream handler only when enabled; expose it as an `http.Handler` factory, not a listener. The factory calls `server.NewServer(scheduler, 0).Router` and is invoked once per enabled process. Recorded decision: upstream `WithAPIDisabled()`/`WithWebSocketDisabled()` MUST NOT be used because removing the `/api` routes would also remove the `GET /api/config`, `GET /api/jobs`, `GET /api/jobs/{id}` reads and `/ws` updates that the read-only dashboard requires; the require-`cron:read`/deny-mutations matrix in the wrapper is therefore the security boundary, not upstream route-registration options.
- `internal/interface/cron/admin/{server.go,auth.go,audit.go,config.go}`: narrow wrapper and `http.Server` factory over the handler, with consumer-owned session/authz/audit interfaces; no `*casbin.Enforcer` or infrastructure concrete type in the interface package. E14-T01 owns starting/shutting down this optional listener in `cmd/cron`.
- `docs/architecture/ADR-023-gocron-ui-security.md`: read-only policy, session boundary, same-origin/CORS defense, and internal-listener constraints.
- Same-origin `POST /admin/session` validates an E09 bearer JWT from the `Authorization` header, authorizes `cron:read`, and mints a down-scoped UI token with only `cron:read` and an expiry ≤5 minutes and no later than the source token. Only the down-scoped token is set in a `Secure`, `HttpOnly`, `SameSite=Strict` cookie; `DELETE /admin/session` clears it. Credentials MUST NOT be placed in a URL or browser local storage.
- Explicit method/path allow-list for session bootstrap/logout, embedded HTML/assets, `GET /api/config`, `GET /api/jobs`, `GET /api/jobs/{id}`, and `/ws`. Deny scheduler mutations `POST /api/jobs`, `POST /api/jobs/{id}/run`, `DELETE /api/jobs/{id}`, and `POST /api/scheduler/{start,stop}`, plus every unknown `/api/*` path.
- Default-off config, loopback bind, dedicated exact HTTPS origin (separate from the public API origin), same-origin Host/Origin enforcement, CSRF policy for session bootstrap/logout, UI rate limiting via E08-T07, and hardening headers. Use a `__Host-` cookie (`Secure`, `HttpOnly`, `SameSite=Strict`, `Path=/`, no `Domain`). After exact origin validation, the wrapper strips `Origin` before invoking upstream and suppresses upstream `Access-Control-*` response headers; it never relies on upstream WebSocket `CheckOrigin`.
- After Host/Origin validation, consult the E08-T07 limiter on every request before any upstream handler or scheduler action. Denial returns 429 with `Retry-After`; store error returns generic 503; neither reaches upstream. Valid authenticated actors use E05-T03 `BuildRateLimitKey("cron-ui", opaqueSubjectID)`; absent/failed authentication and invalid/non-canonical subjects use the fixed `anonymous` ID for the limiter and are denied with a generic 401/403 before any admin action. Subject IDs must be stable, opaque, non-PII, canonical key segments; never use usernames, emails, display names, or forwarded IP headers. Rate budget and window are required positive config values. Forbidden mutation attempts are audited even when rate-limited; audit failure fails closed.
- Unit tests with fake session/authz/audit/limiter seams: route matrix, CORS/WS origin checks, read-only policy, audit of denied controls, disabled-by-default construction, and malformed/canonical actor-key boundaries.

### Out of Scope

- Job implementations and scheduling semantics (E14-T01/T02 own); future safe manual-run capability requires a separate E14 contract/task.
- Public REST exposure (E11 MUST NOT mount this router; Traefik/public ingress wiring is E17 scope, noted only).
- Egress limiter (E09.1-T03) and single-flight (E09.1-T04) behavior.

## Interfaces and Data

```go
// Config{Enabled bool, BindAddr string, PrivateListener bool, AllowedOrigin string,
//   TLSConfig *tls.Config, RateLimitBudget int64, RateLimitWindow time.Duration}
// NewAdminHandler(cfg Config, upstreamFactory func() (http.Handler, error), sessions SessionAuthenticator,
//   tokens TokenVerifier, sessionTokens SessionTokenIssuer, authorizer Authorizer, audit AuditLogger,
//   limiter port.RateLimiter) (http.Handler, error)
// NewAdminServer(handler http.Handler, cfg Config) (*http.Server, error)
// Disabled config yields nil server/handler without invoking upstreamFactory/gocron-ui.
// SessionAuthenticator, TokenVerifier, SessionTokenIssuer, Authorizer and AuditLogger are narrow interfaces.
// RateLimiter key uses service.BuildRateLimitKey("cron-ui", opaqueSubjectID), or
//   service.BuildRateLimitKey("cron-ui", "anonymous") before/when auth is absent or invalid.
// opaqueSubjectID is stable, non-PII, already canonical, 1..128 bytes, and contains
//   no colon or control characters; invalid subject -> anonymous limiter key + deny.
// Bootstrap issues a distinct token carrying only "cron:read"; TTL <= 5m and <= source JWT expiry.
// Scope: "cron:read" only. E11 integration: none (explicit non-route).
```

## Invariants and Failure Semantics

- This task is read-only. Raw gocron `RunNow`, `RemoveJob`, `Start`, and `StopJobs` MUST never be reachable: they can bypass durable run keys, leader coordination, and fencing. Construct the upstream broadcaster only for the single enabled process-lifetime UI instance.
- The only token issuance is a down-scoped, short-lived `cron:read` UI session after validating and authorizing the source E09 bearer token; the source token is never placed in the cookie. The task does not edit RBAC policies or rewrite audit chains. Logout expires the cookie; any copied UI token remains unusable for more than its ≤5-minute TTL.
- A non-loopback listener is rejected unless private-listener mode, TLS client-certificate verification, and the E17 network policy are present; loopback remains the default.
- Fail closed: auth/session error, scope denial, limiter error, disabled flag, or audit failure cannot reach the upstream handler/scheduler for a protected action.
- No secret in logs/traces; token content never logged; WebSocket messages expose only the job data already authorized for `cron:read`.
- Do not put an arbitrary JWT `sub` directly into Valkey: only canonical, opaque non-PII actor IDs meeting E05-T03 segment rules may form actor keys. Invalid values are not repaired or truncated and cannot reach the admin action.
