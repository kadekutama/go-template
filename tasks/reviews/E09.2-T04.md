Task E09.2-T04 delivers the continuous profiling infrastructure adapter (`internal/infrastructure/profiling/`) utilizing `github.com/grafana/pyroscope-go v1.4.3` and `github.com/grafana/otel-profiling-go v0.7.0` (ADR-027). 6. **DI Integration & Lifecycle Verification (R07, S04):** `profiling.Module()` is cleanly registered in `internal/shared/di/infrastructure.go:InfrastructureModule` with a default-disabled configuration. Graph resolution is proven with `fx.ValidateApp`, and ordered hook execution is verified with `fxtest.New`.

## Non-blocking Observations

1. **Unobservable Block Profile Rate Getter:** Go's runtime package exposes `runtime.SetMutexProfileFraction(-1)` to query the active mutex fraction, but offers no corresponding query function for `runtime.SetBlockProfileRate`. Testing the mutex profile fraction reset upon `Stop()` serves as a reliable proxy that the adjacent `runtime.SetBlockProfileRate(0)` reset has executed.
2. **Future Composition Root Configuration:** Currently, `InfrastructureModule` supplies `profiling.DefaultConfig()` (disabled). As binary entry points are implemented in later epics (E11/E14), they should map `appConfig.Observability.Profiling.Profiling()` and pass it to `InfrastructureModule(cfg)` to enable operator configuration from YAML and environment variables.
