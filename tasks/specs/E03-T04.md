# Task Specification: E03-T04 — Fee calculation + interest accrual domain rules

**Task:** E03-T04
**Spec Status:** ready
**Author:** opencode-agent
**Reviewer:** repo-owner
**Last Updated:** 2026-09-14

## Objective

Ship pure fee (basis points + cap/floor, monthly tiers) and interest (Actual/365 daily) calculation rules with template entry construction.

## Scope

### In Scope

- `internal/domain/service/fee_service.go`: per-transaction bps + cap/floor, monthly tier schedule, template entries (DR merchant payable / CR platform revenue), processor vs platform fee split.
- `internal/domain/service/interest_service.go`: daily rate = annual/365, direction by account class, zero/negative guard, INTEREST posting-line shape.

### Out of Scope

- Scheduling/cron (E14); persistence; API.

## Normative Inputs

- `tasks/epics/E03-money-movement.md#E03-T04` for the backlog boundary.
- `docs/ledger-core.md §4` (checked int64 math, one rounding boundary, largest-remainder), `docs/money-flow.md §2.6`, `docs/domain-events.md §3.10`.

## Requirements

| ID | Requirement | Priority |
|----|-------------|----------|
| E03-T04-R01 | Per-transaction fee MUST be amount×bps/10000 clamped to [floor, cap] with checked math. | must |
| E03-T04-R02 | Monthly tier fees MUST select the tier by volume and apply its bps schedule. | must |
| E03-T04-R03 | Fee entries MUST debit merchant payable and credit platform revenue; processor vs platform fees tracked separately. | must |
| E03-T04-R04 | Daily interest MUST be balance×annualBps/10000/365 (Actual/365) with leap-day table behavior. | must |
| E03-T04-R05 | Zero/negative balances MUST accrue nothing. | must |
| E03-T04-R06 | New code MUST import only stdlib + `internal/domain/...`. | must |
| E03-T04-R07 | A zero-bps schedule MUST assess zero (explicit free tier) without applying the floor. | must |
| E03-T04-R08 | Fee splits MUST satisfy total == processor + platform with non-negative parts (`SplitFee`). | must |

## Executable Scenarios

| E03-T04-S04 | zero/negative balance | AccrueDaily | 0, no posting |

## Invariants and Failure Semantics

- Checked int64 math, overflow → error. No floats. Direction: asset/expense accrue debit-side, liability/equity/revenue credit-side (display only; entries explicit).
