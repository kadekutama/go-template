# Task Specification: E09-T01 — JWT (RS256) issuance + validation + rotation

**Task:** E09-T01
**Spec Status:** ready
**Author:** muse-spark
**Reviewer:** kadekutama
**Last Updated:** 2026-09-23

## Objective

Deliver RS256 JWT issuance/verification behind `port.TokenIssuer` with `kid` rotation, short-lived access tokens, and single-use refresh rotation with family revocation.

## Scope

### In Scope

- `internal/infrastructure/auth/jwt/` package: keys (generate/import, `kid` registry, rotation with overlap), issuer (`Issue`), validator (`Verify`), JWKS publish, refresh family store with reuse detection.
- `Module() fx.Option` exposing `port.TokenIssuer`.
- Unit tests with real RSA keys (no network, no Docker).

### Out of Scope

- OAuth2/OIDC login (E09-T02), Casbin decisions (E09-T03), API keys (E09-T04), OpenBao key sourcing wire-up beyond `SecretStore` lookup (E09-T05 consumes).

## Normative Inputs

- `tasks/epics/E09-identity-security.md#E09-T01` for the backlog boundary.
- `SPEC.md §7.4` (RS256, 15m access, 7d rotating refresh) and `SPEC.md §7.10` (port seam).
- `internal/application/port/token.go` (`TokenClaims`, `TokenIssuer{Issue,Verify}` contract).
- `docs/development/go-conventions.md` (Params pattern, private fields, pointer receivers for services).

## Requirements

| ID | Requirement | Priority |
|----|-------------|----------|
| E09-T01-R01 | The issuer MUST mint RS256 tokens with `kid` header, `sub`, `tenant_id`, `scopes`, `iat`, `exp` claims and MUST sign with the active key. | must |
| E09-T01-R02 | The validator MUST reject expired, tampered, wrong-audience/issuer, and unknown-`kid` tokens with distinct errors and MUST fail closed. | must |
| E09-T01-R03 | Rotation MUST keep the previous key valid until grace expiry and MUST publish both keys via JWKS (`keys` with `kty`, `kid`, `n`, `e`). | must |
| E09-T01-R04 | Refresh rotation MUST be single-use: reuse of a spent refresh token MUST revoke the whole family and MUST fail subsequent uses. | must |
| E09-T01-R05 | Keys MUST come from injected `KeyProvider` (OpenBao `SecretStore` in prod, in-memory in tests); private key material MUST never hit logs/errors. | must |
| E09-T01-R06 | The adapter MUST implement `port.TokenIssuer` exactly and MUST expose `Module() fx.Option`. | must |

## Executable Scenarios

| ID | Given | When | Then |
|----|-------|------|------|
| E09-T01-S01 | Valid claims | `Issue` then `Verify` | Same subject/tenant/scopes round-trip, no error |
| E09-T01-S02 | Expired/tampered/wrong-`kid` token | `Verify` | Distinct errors, fail closed |
| E09-T01-S03 | Rotated keys within grace | `Verify` old-`kid` token | Passes until grace expiry, then rejected |
| E09-T01-S04 | Spent refresh token replay | Second `UseRefresh` | Family revoked, all tokens in family rejected |
| E09-T01-S05 | Canceled context | `Issue`/`Verify` | Context error, no token minted |

## Invariants and Failure Semantics

- Verification is strongly consistent against current keys; revoked/expired tokens fail closed.
- Tokens never substitute for command-level `Authorizer` checks.
- Clock is injected; `ctx` deadlines honored; secrets never logged.

**Amendment 2026-09-23 (durable-boundary review, ADR-020):** No app mutexes or
in-memory security state. Keys load from OpenBao `SecretStore` into an
`atomic.Pointer` RCU snapshot (lock-free reads, rotation swaps the snapshot);
refresh families/receipts live in PostgreSQL (`20260923000006`, unique token
hash → reuse detected by constraint, no mutex). JWKS renders from the snapshot
via `ActiveSet()`, never reaching into provider locks.
**Amendment 2026-09-25 (review round 3, Antigravity Agent):** Added `NextToken string` to
`RefreshClaim` so callers receive the successor token on rotation. Refactored `IssueRefresh`
and `UseRefresh` to use standard `postgres.WithinTenantTx` runner. Added `ctx.Err()` fast-abort.

**Amendment 2026-10-01 (GLM review fix round, CR-007 + R02 ruling):**
`SnapshotProvider.Swap` merges under a CAS retry loop (concurrent rotations no
longer drop keys). R02 ruling recorded: expired/tampered/unknown-kid rejections
carry distinct sentinels (`ErrExpired`, `ErrInvalidSignature`, `ErrUnknownKeyID`);
wrong-audience and wrong-issuer share `ErrInvalidClaims` with distinct messages
("audience mismatch" / "issuer mismatch") — explicitly accepted as the R02
meaning of "distinct errors" for the aud/iss pair. Rollback: restore Store-based
swap; split aud/iss sentinels (packet + code change).
