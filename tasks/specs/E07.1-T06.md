# Task Specification: E07.1-T06 — UUIDv7 composite identity re-baseline (persistence)

**Task:** E07.1-T06  
**Spec Status:** ready  
**Author:** muse-spark  
**Reviewer:** repository-owner  
**Last Updated:** 2026-09-17

## Objective

Re-baseline persistence on DB-generated native UUIDv7 identity with
composite tenant-first primary keys per ADR-019, unlocking Citus
distribution for the core tables while keeping replay safety, RLS, and
trigger semantics intact.

## Scope

### In Scope

- Rewrite the four baseline files in place (now timestamped `20260901000001`–`20260901000004` per owner directive; history renumbered once, pre-release): `UUID DEFAULT uuidv7()` identity
  columns, `PRIMARY KEY (tenant_id, id)` on ledgers/accounts/postings/
  entries/holds (tenant-first checkpoints), `UUID`-typed `tenant_id` FK
  columns, `::uuid` casts in RLS policies, `tenants.alias` global UNIQUE +
  `ledgers.alias` per-tenant UNIQUE.
- Extend `20260901000005_citus_distribution.sql` table list to the newly
  distributable set (accounts, holds, ledgers, idempotency_records);
  resilient NOTICE + WARNING posture unchanged.
- Regenerate `atlas.sum`; `goose validate`; prove Up/Down on PostgreSQL and
  Citus coordinator.
- GORM models: `type:uuid` string fields, composite keys, `RETURNING`
  round-trip proof (fallback: `uuid.UUID` model type, recorded if taken).
- Repositories: string↔UUID mapping at the port boundary, tenant-scoped FK
  writes, tenant-closed reads unchanged.
- Fixtures: canonical-UUID literals under preserved constant names;
  `testcontainers`/integration expectations that assert IDs or versions.

### Out of Scope

- Alias assignment rule and provider-key audit (owned by E06-T14).
- Domain value objects (already UUID-shaped; untouched) and domain rules.
- Postings/entries trigger-safe distribution and outbox constraint redesign
  (named follow-ups; resilient path covers them).
- Docker image / CI pipeline changes (E17).

### Amendment 2026-09-17 (owner-directed full DB-generation)

Repository `Create`/`Commit` ports return the persisted entity so handlers
read database-assigned IDs instead of pre-minting. Whoever changes an
interface updates all its callers in the same task: T06 therefore owns the
mechanical conversion end to end (ports, repos, mocks, callers, fixtures,
suites). E06-T14 keeps application semantics (alias, provider audit, replay
proofs). `domain/repository` ports are E02-owned; this amendment names them
explicitly for E02 reviewer visibility.

### Amendment 2026-09-17 (rescoped conversion; owner-approved full track)

Caller conversion splits for atomicity: T06 adapts callers minimally (use
returned entities, pre-mint retained — behavior-identical, tree stays
green). E06-T15 removes entity pre-mint, opens aggregate/service
constructors to empty IDs, and updates their tests. E06-T14 keeps alias
assignment, provider-key audit, and replay proofs.

## Interfaces and Data

- Column map (representative; full matrix in the migration files):
  `ledgers/accounts/postings/entries/holds.id`: `TEXT` → `UUID DEFAULT uuidv7()`;
  their PKs → `(tenant_id, id)`; `tenant_id` columns `TEXT` → `UUID`;
  `tenants.id` → `UUID DEFAULT uuidv7()` + `alias TEXT UNIQUE`;
  `ledgers.alias TEXT` + `UNIQUE (tenant_id, alias)`.
- GORM: `ID string \`gorm:"type:uuid;primaryKey;default:uuidv7()"\`` with
  composite keys declared per model; `RETURNING` refresh proven by test.
- No application or domain interface changes in this task.

## Invariants and Failure Semantics

- Double-entry balance, posting immutability, hold state machines, and
  per-asset checks are behavior-identical; only key shapes change.
- Explicit-ID inserts (fixtures, replays) keep working: `DEFAULT` applies
  only to omitted columns.
- RLS fail-closed posture preserved, now with `::uuid` casts.
