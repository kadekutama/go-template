## Objective

Give the repository-local reviewer agent OpenCode V2 frontmatter so its
review-only posture is enforced by tool permissions rather than prompt
instruction alone, while guaranteeing write access to the SDD review-record
files it is required to produce.

## Scope

### In Scope

- Prepend a YAML frontmatter block to `.opencode/agents/reviewer.md`
  (description, mode, permissions). The prompt body below the block stays
  byte-identical.
- Permissions: deny edits everywhere except `tasks/reviews/**` (allow), deny
  shell by default with narrow `ask` gates for read-only git inspection and
  the two repository checkers, deny subagent launches.
- Task index/progress totals for the new task.

### Out of Scope

- Any change to the reviewer prompt body (user-authored content).
- Pinning a `model:` override (owner decides; agent inherits the parent
  session's model until then).
- Runtime enforcement testing inside a live OpenCode session (environmental
  limitation; recorded under Not Verified).
- Any implementation (non-test Go), migration, contract, or E09 change.

## Normative Inputs

- OpenCode V2 agents documentation (`opencode.ai/v2/docs/agents/`):
  frontmatter fields, permission rule shape `{action, resource, effect}`,
  last-match-wins ordering, mode semantics.
- `tasks/SDD.md` §2 (reviewer may write only the review artifact), §6
  (review artifact authorization), §8 (harness adapters are thin).
- `.opencode/agents/reviewer.md` (current body).
- `tasks/tracking/GATES.md` §G1.

## Invariants and Failure Semantics

- The reviewer's write surface is exactly `tasks/reviews/**`; the evidence
  `## Code Review` fallback in the prompt body is intentionally NOT writable
  by the agent — if the review path is not authorized, the reviewer reports
  in-chat and the task owner persists it (SDD §2).
- `mode: all` keeps both entry paths (selector as primary, subagent launch);
  selector use still means a primary session governed by these permissions.
- Model is inherited until the owner pins an override.
