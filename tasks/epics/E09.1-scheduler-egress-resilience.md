### E09.1-T02: gocron-ui secure internal ops surface
**Status:** pending
**Background:** Pin `gocron-ui` v0.3.0 as a read-only internal dashboard. Its upstream router is unauthenticated by default, allows wildcard CORS and all WebSocket origins, registers `POST /api/jobs` despite the README omission, and exposes direct scheduler controls. Do not expose the upstream router unwrapped. The UI remains read-only in this task: raw `RunNow`, job deletion/creation, and scheduler start/stop can bypass durable run-key, leader, and fencing rules.
**Files:**
- Create: `internal/infrastructure/cronui/handler.go`, `internal/interface/cron/admin/{server.go,auth.go,audit.go,config.go}` + unit tests; exact `gocron-ui v0.3.0` module pin and `SPEC.md §2` row.
- Create: `docs/architecture/ADR-023-gocron-ui-security.md`; coordinate E09 JWT/session verification, authorization and audit ports (interfaces only; concrete Casbin/JWT/audit adapters stay behind the composition root).
**Steps:**
1. Add same-origin `POST /admin/session`: validate an existing E09 bearer JWT from the `Authorization` header, require `cron:read`, then mint a short-lived (≤5-minute, no later than the source token) read-only UI token with only the `cron:read` scope. Set only that down-scoped token in a `Secure`, `HttpOnly`, `SameSite=Strict` cookie; `DELETE /admin/session` clears it. Never accept credentials in URLs/local storage or put the original bearer token in a cookie. Auth applies to HTML/assets, `/api/config`, `/api/jobs`, `/api/jobs/{id}`, and `/ws`.
2. Use a strict method/path allow-list. Read routes are `GET /api/config`, `GET /api/jobs`, and `GET /api/jobs/{id}` plus the embedded UI/static assets and `/ws`; require `cron:read`. Deny `POST /api/jobs`, `POST /api/jobs/{id}/run`, `DELETE /api/jobs/{id}`, and `POST /api/scheduler/{start,stop}` regardless of role, plus every unknown `/api/*` route. Record denied control attempts without credentials or sensitive payloads. Any future mutation needs a separate safe E14 control contract and task.
3. Enforce exact Host/Origin checks before the upstream handler. After validation, pass a request clone with `Origin` removed and suppress upstream `Access-Control-*` response headers so wildcard CORS cannot authorize cross-origin access; never rely on upstream WebSocket `CheckOrigin`. Add CSRF protection to session bootstrap/logout. The UI is disabled by default and constructed only when enabled; one instance per process.
4. Bind loopback by default. Any non-loopback bind requires explicit private-listener mode, verified mTLS client certificates, and the E17 private-network policy. E11 MUST NOT mount this handler and public ingress MUST NOT route to it. Apply the E08-T07 limiter to UI requests using only canonical opaque non-PII subject IDs validated by the E05 key builder; malformed subjects use the anonymous limiter bucket and are denied.
**Acceptance Criteria:**
- [ ] Unauthenticated HTML/assets, REST, and WS → 401; a `cron:read` session can view schedules; all mutation routes (including `POST /api/jobs`) are denied and audited without reaching the scheduler.
- [ ] Cross-origin requests and WebSocket upgrades are rejected; no wildcard CORS headers are emitted.
- [ ] UI disabled by default: no upstream UI instance, listener, or broadcaster goroutine is created; E11 has no route to it.
- [ ] Non-loopback mode requires verified mTLS client certificates and is unusable until E17's private network policy is in place.
**Story Points:** 5
**Depends On:** E05-T03, E09.1-T01, E09-T01, E09-T03, E09-T07
**Related Docs:** `SPEC.md §8.4`, `SPEC.md §7.4`, `SPEC.md §14`, `tasks/epics/E09-identity-security.md#E09-T01`, `tasks/epics/E09-identity-security.md#E09-T03`, `tasks/epics/E09-identity-security.md#E09-T07`

### E09.1-T03: Distributed egress rate limiter over Valkey
**Status:** pending
**Background:** E08-T07 already provides an atomic Valkey token bucket through `port.RateLimiter`. Add an egress-specific blocking `Wait` policy over that adapter and provider-operation keys built with E05-T03; do not add another Lua script or alter E08-T07’s accepted caller-clock contract. E10 provider tasks consume this capability for each attempt.
**Files:**
- Create: `internal/infrastructure/egress/{limiter.go,params.go,config.go}`, `test/integration/egress-limiter/` (Testcontainers burst test), and unit tests; provider-policy schema/docs in `config/egress/` and `config/schemas/egress-policy.json`.
- Create: `docs/architecture/ADR-024-provider-egress-rate-limits.md`.
- Coordinate: `port.RateLimiter` and E08-T07 adapter (consume as-is; do not modify its Lua script or guard).
**Steps:**
1. Define `EgressLimiter.Wait(ctx, provider, operation)` over the existing `port.RateLimiter`, using E05-T03 `BuildRateLimitKey(provider, operation)` to produce `ratelimit:{provider}:{operation}` keys, with validated per-provider budget/window/max-wait configuration. Use only positive jitter after `RetryAfter`; return a typed max-wait error and stop promptly on context cancellation.
2. Preserve the existing single Lua script and caller-clock behavior. Document that provider hosts require synchronized clocks; test the same token-bucket burst/refill semantics as E08-T07. No second Lua file or E08 guard amendment is allowed.
3. Specify call composition for E10: retry loop → egress `Wait` → breaker-wrapped single provider attempt → `httpclient.Doer`. Each retry reacquires a permit; limiter/store errors are terminal for that call and are not counted as provider-breaker failures. Limiter-store errors fail closed for outbound requests; callers may serve cached/stale reads without making a provider call.
**Acceptance Criteria:**
- [ ] With a fresh bucket and bounded `maxWait` shorter than one refill interval, exactly the initial bucket capacity is admitted; remaining callers time out without exceeding the token-bucket budget (Testcontainers).
- [ ] Pre-canceled contexts perform no `Allow`; cancellation during a denied wait stops before another `Allow`. A cancellation racing with an atomic successful reservation may consume that permit and is never refunded.
- [ ] The repository still contains only E08-T07’s `ratelimit.lua` as a `redis.call` script.
- [ ] Provider-operation policies require positive configured budget/window/max-wait; missing policy or malformed denied decision fails closed without an unmetered call or retry spin.
**Story Points:** 4
**Depends On:** E01-T08, E05-T03, E06-T12, E08-T07, E09.1-T02
**Related Docs:** `SPEC.md §9.4`, `SPEC.md §7.8`, `SPEC.md §7.10`, `tasks/epics/E08-cache-messaging.md#E08-T07`, `tasks/specs/E05-T03.md`, `tasks/specs/E06-T12.md`

### E09.1-T04: Local single-flight for cacheable reads
**Status:** pending
**Background:** Concurrent identical cacheable reads can stampede a provider when multiple goroutines miss the same cache key. `golang.org/x/sync/singleflight` collapses in-process duplicates. Cross-node coalescing is deferred until duplicate provider load is measured after the cache and worker paths are in use. This task follows T03 to serialize E09.1 task/progress updates; it also owns a later direct `go.mod` pin update.
**Files:**
- Create: `internal/infrastructure/cache/coalesce/{singleflight.go}` + unit tests (concurrent-miss collapse, error non-caching, context cancel)
- Modify: `go.mod` / `go.sum` (promote `golang.org/x/sync` to direct); `SPEC.md §2` (record the exact v0.23.0 pin)
- Coordinate: `internal/infrastructure/cache/hybrid/**` (read-only; no engine semantics change)
**Steps:**
1. Add `Coalescer.Do(ctx, CoalesceKey, fn)` over `singleflight.Group` using `DoChan`; each waiter may cancel independently. Shared work uses `context.WithTimeout(serviceOwnedBaseContext, configuredHardTimeout)` and remains credential-free: caller contexts control waiting only, while service shutdown still cancels shared work.
2. Allow only explicit cacheable-read enum values; reject unknown/money-moving kinds. Keys include provider, tenant/authorization scope, and a non-PII request-identity digest. Provider/session-specific credentials or responses MUST NOT be shared across scopes.
3. Do not cache results or errors after the in-flight call completes. Return cloned byte slices per caller. E10-T02 applies the coalescer only around FX cache-miss fetches; payment writes are prohibited.
**Acceptance Criteria:**
- [ ] 50-way concurrent identical read executes `fn` exactly once; each non-canceled waiter receives equal bytes backed by its own slice.
- [ ] Errors are not retained after the in-flight call; cancellation of the first caller and a later waiter does not cancel other waiters; the shared call is bounded by its configured timeout.
- [ ] Service shutdown cancels active shared work; caller cancellation alone does not.
- [ ] Money-moving operations are rejected by the coalescer API, and different provider/authorization scopes use distinct in-flight keys.
**Story Points:** 3
**Depends On:** E01-T08, E06-T12, E08-T01, E09.1-T03
**Related Docs:** `SPEC.md §7.8`, `SPEC.md §7.10`, `SPEC.md §7.3`, `tasks/epics/E08-cache-messaging.md#E08-T01`
**SDD Gate:** G4
