## Objective

Enforce per-provider outbound quotas across all replicas with blocking `Wait` semantics on the existing `port.RateLimiter`, so retries and bursts cannot multiply a vendor quota by replica count.

## Scope

### In Scope

- `internal/infrastructure/egress/{limiter.go,params.go,config.go}`: `EgressLimiter.Wait(ctx, provider, operation)` over the existing `port.RateLimiter`, with provider-operation keys, per-provider budget/window/maxWait, bounded positive jitter, context cancellation, and validated policy loading.
- `config/schemas/egress-policy.json` and `config/egress/README.md`: provider policy format. E10 owns separate provider files (`config/egress/{unleash,fx,payment-processor,smtp}.yaml`) to avoid shared-file collisions.
- `docs/architecture/ADR-024-provider-egress-rate-limits.md`: provider keying, fail-closed outage semantics, retry placement, and reuse of the E08 token bucket/caller-clock contract.
- Provider-attempt composition contract for E10: retry loop → egress `Wait` → breaker-wrapped single provider attempt → `httpclient.Doer`.
- Fake `port.RateLimiter` unit tests + `test/integration/egress-limiter/**` Testcontainers Valkey burst test through the existing E08 adapter. Do not add or modify Lua scripts.

### Out of Scope

- Ingress 429 mapping (E08-T07 + E11 own); per-tenant inbound overrides stay untouched.
- Single-flight coalescing (E09.1-T04); Resty or any HTTP client swap (explicit non-goal).
- Provider adapter call sites (E10-T01/T02/T03/T05 consume the limiter; this task ships the validated primitive + wiring contract).
- Changes to `internal/infrastructure/cache/valkey/ratelimit.lua` or the E08-T07 Lua guard.

## Executable Scenarios

| ID | Given | When | Then |
|----|-------|------|------|
| E09.1-T03-S01 | Fresh token bucket, capacity 10, maxWait shorter than one refill interval | 20 concurrent `Wait` calls | Exactly the initial capacity is admitted; remaining callers return wait-exceeded; no permit is over-issued (Testcontainers) |
| E09.1-T03-S02 | Context canceled before `Wait` or while sleeping after a denial | `Wait` | Pre-cancel performs no port call; in-wait cancel stops before another port call. A cancellation racing with a successful atomic reservation may consume that permit; it is not refunded. |
| E09.1-T03-S03 | Empty provider/operation or non-positive budget/window/maxWait | `Wait` | Typed validation error before the port is called |
| E09.1-T03-S04 | A retryable provider error causes another attempt | E10 attempt wrapper | Every attempt calls `Wait`; a limiter error terminates before breaker/provider and is not retried |
| E09.1-T03-S05 | Repo-wide Lua scan | `grep -rn "redis.call" --include="*.lua" .` | Only `internal/infrastructure/cache/valkey/ratelimit.lua` matches |
| E09.1-T03-S06 | Missing or invalid provider policy | Load config or construct limiter | Typed validation error; no implicit unlimited policy |
| E09.1-T03-S07 | RateLimiter returns denied with zero/negative RetryAfter | `Wait` | Typed malformed-decision error; no tight retry loop |

## Interfaces and Data

```go
// EgressPolicy{Provider, Operation string; Budget int64; Window, MaxWait time.Duration}
// Config file shape: policies: [{provider, operation, budget, window, max_wait}]
// All fields are required; no default/unlimited quota is accepted.
// EgressParams{Limiter port.RateLimiter, Policies []EgressPolicy,
//   Clock Clock, Jitter JitterSource, Sleeper Sleeper}
// NewEgressLimiter(EgressParams) (*EgressLimiter, error)
// func (l *EgressLimiter) Wait(ctx context.Context, provider, operation string) error
// Key: service.BuildRateLimitKey(provider, operation), yielding
//   "ratelimit:{provider}:{operation}"; token-bucket Eval/Lua remains owned by E08-T07.
// Call order per attempt: Retry.Execute(attempt => EgressLimiter.Wait -> Breaker.Execute(Doer.Do))
```

## Invariants and Failure Semantics

- Keys are provider-operation scoped, use E05-T03's colon-safe builder, and contain no tenant PII. The existing Valkey Lua caller-clock behavior is intentionally unchanged; deployment hosts must maintain synchronized clocks.
- The limiter is an outbound admission boundary, not a 429 mapper. Limiter errors fail closed and are terminal for the current provider operation; they are not provider failures.
- Positive jitter never retries before the returned `RetryAfter`. A permit reserved atomically before a caller cancellation is not refundable.
