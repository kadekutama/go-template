## Objective

Deliver at-least-once relay: outbox poller publishes to Redpanda via `port.EventPublisher`, idempotent consumer dedupes on fact/message identity with DLQ, and edge deltas bridge to NATS Core.

## Scope

### In Scope

- `internal/infrastructure/messaging/redpanda/publisher/redpanda.go`: encode via `pkg/jsonparser`, headers (fact identity, trace), partition on `tenant_id:account_id`; called by E07 outbox poller.
- `internal/infrastructure/messaging/redpanda/consumer/framework.go`: envelope/schema validation → inbox receipt insert → handler → commit → ack; duplicate skips effects and acks; failure retries then DLQ.
- `internal/infrastructure/messaging/redpanda/consumer/idempotent.go`: in-memory + Valkey-backed receipt store (durable postgres inbox owned by E07 schema; this task proves effectively-once effects).
- `internal/infrastructure/messaging/redpanda/consumer/dlq.go`: max-delivers routing + replay hook.
- `internal/infrastructure/messaging/nats/publisher.go` (`PublishEvent`): delta publish to NATS for active WebSockets (contract-level subject bridge over the NATS transport).
- Implements `port.EventPublisher` + `port.MessageConsumer` transport.

### Out of Scope

- Broker topology (E08-T03), webhook business delivery (E08-T05), worker group wiring (E14), ledger command replay (forbidden).

## Requirements

| ID | Requirement | Priority |
|----|-------------|----------|
| E08-T04-R01 | Publisher MUST encode facts via `pkg/jsonparser`, set identity/trace headers, and partition on `tenant_id:account_id`. | must |
| E08-T04-R02 | Consumer MUST validate input, claim the `(consumer,event_id)` receipt, run the handler, then ack; duplicates MUST skip effects and ack. | must |
| E08-T04-R03 | Failures MUST release the receipt (rollback per `docs/domain-events.md §5.2`), retry until max delivers, then route to DLQ; DLQ records MUST retain redelivery count. | must |
| E08-T04-R04 | Consumers MUST apply read-side effects only; event replay MUST NEVER re-run ledger commands. | must |
| E08-T04-R05 | Trace/request IDs from ctx MUST be emitted into the envelope body and transport headers by the publisher and MUST be restored onto the handler ctx by the consumer framework (asserted end-to-end in test). | must |
| E08-T04-R06 | Edge bridge MUST publish delta notifications to NATS without blocking ack. | must |
| E08-T04-R07 | DLQ routing MUST release the inbox receipt (no effect committed) so a DLQ replay after an operator fix re-runs the handler instead of being swallowed as a duplicate. | must |
| E08-T04-R08 | A release failure MUST be joined with the handler error and returned (redeliver, safe direction); exhausted messages with no DLQ sink MUST return the handler error for the caller's policy. | must |

## Executable Scenarios

| ID | Given | When | Then |
|----|-------|------|------|
| E08-T04-S01 | Committed fact | Publish then kill+redeliver | Handler executed once |
| E08-T04-S02 | Duplicate delivery | Consumer receives same ID | Skipped effects, acked |
| E08-T04-S03 | Handler fails N times | Redelivery loop | Retried, receipt released each attempt, then DLQ with count |
| E08-T04-S04 | Ctx carries trace/request IDs | Publish then Handle envelope | Same IDs observed in handler ctx; non-envelope payloads pass through |
| E08-T04-S05 | Replay of old event | Consumer runs | No ledger command invoked (read-side assertion) |
| E08-T04-S06 | Poison reaches DLQ | DLQ replay of the same message | Receipt was released on DLQ, so the replay re-runs the handler (not a duplicate ack) |
| E08-T04-S07 | Receipt release fails | Handler also failed | Caller sees both errors (joined), message redelivers |
| E08-T04-S08 | Exhausted, no DLQ sink | Handler keeps failing | Handler error returned each delivery (no silent ack) |

## Invariants and Failure Semantics

- At-least-once delivery; effectively-once effects via receipt identity.
- The receipt is released on every failure path, including DLQ routing (domain-events §5.2 rollback model): no effect committed ⇒ no claim retained.
- Unknown outcome ⇒ redeliver; poison ⇒ DLQ, never silent drop.
- Panics in handlers are recovered per SPEC §9.7 (Nak + backoff, then DLQ), and follow the same receipt-release rule.
