## Findings

### CR-001 — Shell allow-list bypassed edit approval [Medium] [Risk] — FIXED
- **Location:** `.opencode/agents/implementer.md:17-19`; shell permission block.
- **Issue:** Prefix-based shell allow exceptions could match commands with
  redirection, for example `git status --short --branch > file`, so shell could
  write without the `edit: ask` approval gate.
- **Why it matters:** The configured permission boundary did not guarantee an
  owner prompt before a shell operation that writes a file.
- **Evidence:** OpenCode V2 permission matching evaluates shell command text;
  the prior profile placed command-prefix `allow` rules after the catch-all
  `shell: ask`, so the later matching rule won.
- **Plan violation:** E18-T14-R01; shell allow exceptions violated the intended
  approval boundary.
- **Expected behavior:** Every shell invocation requires owner approval.
- **Recommended fix:** Remove shell allow exceptions and retain only
  `shell: * → ask`.
- **Verification:** Normalized permission probe found exactly one shell entry
  (`resource: "*"`, `effect: ask`); no shell allow entries remain.
- **Resolution:** Fixed in `.opencode/agents/implementer.md`; structural/docs,
  G1, lint, and race checks passed. The fix is uncommitted pending owner
  direction, so this report is not a release approval.

### CR-002 — Broad read allow silently overrides the platform's `.env` protection [Medium] [Risk] — FIXED
- **Location:** `.opencode/agents/implementer.md:5-7` — read permission block.
- **Issue:** The profile's `read * → allow` is appended after OpenCode's base
  policy (`read *.env → ask`, `read *.env.* → ask`, `read *.env.example → allow`);
  last-match-wins resolution let the broad rule silently permit workspace
  `.env` reads without any approval prompt.
- **Why it matters:** Secret files inside the workspace could be read silently,
  defeating the profile's approval-gated posture; the same pattern exists in
  `.opencode/agents/reviewer.md`.
- **Evidence:** OpenCode V2 docs ("Every agent... starts with this ordered base
  policy"; "Later global and agent rules can override these defaults"; "the last
  matching rule wins"); no `.env`-specific rule existed in the profile.
- **Plan violation:** Amendment E18-T14-R04 (added 2026-10-04T08:16:28Z,
  owner-approved); the original R03 pinned read rules unchanged, so the packet
  was amended first per SDD packet-first rule.
- **Expected behavior:** Workspace `.env`/`.env.*` reads ask; `.env.example`
  and ordinary reads stay allowed.
- **Recommended fix:** Append `*.env → ask`, `*.env.* → ask`,
  `*.env.example → allow` after the broad read allow.
- **Verification:** Last-match resolution probe: `.env`, `config/.env`,
  `.env.local`, `deployments/.env.prod` → ask; `.env.example`, `README.md`,
  Go sources → allow; 9 permission entries asserted.
