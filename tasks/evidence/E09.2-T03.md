### Remediation detail

`nilaway` reported a single interprocedural nil flow in `internal/infrastructure/audit/chain.go`:

- Source: `var next []string` inside `merkleTreeRoot` starts nil.
- Flow: `current = next` after the level loop; `return current[0]` then indexes a possibly-nil slice.

Fix (contract-preserving, one production file):

```go
for len(current) > 1 {
    // Allocate a non-nil level buffer so the final current[0] dereference
    // cannot be a nil flow for the interprocedural nil analysis.
    next := make([]string, 0, len(current))
    ...
    current = next
}
```

The buffer is now non-nil on every iteration while the append/hash behavior is unchanged (the inner loop still appends exactly one hash per pair, and `merkleTreeRoot`'s empty-input guard is untouched). Existing `TestMerkleTreeRoot` cases cover empty, single-leaf, odd, even, and multi-level trees; no test contract changed. The initial capacity (`len(current)`) is an upper bound that avoids a magic-number divisor; `mnd` stays clean.
