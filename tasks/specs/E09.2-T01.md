## Objective

Adopt `github.com/samber/lo v1.53.0` as an approved pure generic collection utility library across all layers (`domain`, `application`, `infrastructure`, `interface`, `shared`), configure `.golangci.yml` (`depguard` and `forbidigo`) to mechanically block `lo/parallel` and `lo` retry/concurrency helpers (`lo.Attempt*`, `lo.Async*`, `lo.Transaction*`, `lo.NewDebounce*`, `lo.Synchronize*`, `lo.WaitFor*`), and refactor repetitive collection boilerplate across `internal/domain/`, `internal/application/workflow/`, and `internal/infrastructure/`.

## Scope

### In Scope

- `go.mod` / `go.sum`: pin `github.com/samber/lo v1.53.0` and run `go mod tidy`.
- `internal/shared/deps/deps.go` & `internal/shared/deps/deps_test.go`: add blank import anchor `_ "github.com/samber/lo"` and table-driven smoke test for `lo.Map`, `lo.KeyBy`, `lo.GroupBy`, and `lo.UniqMap`.
- `.golangci.yml`:
  - Allow exactly `github.com/samber/lo` (root package) in `depguard.rules.{domain,application,composition-roots}.allow`.
  - Deny `github.com/samber/lo/parallel`, `github.com/samber/lo/mutable`, and `github.com/samber/lo/it` in `depguard.rules.{domain,application,interface,infrastructure,shared,composition-roots}.deny`.
  - Configure `forbidigo` to ban the retry/async helpers (`lo.Attempt*`, `lo.Async*`, `lo.NewDebounce*`, `lo.Synchronize*`, `lo.WaitFor*`) and the transaction/channel/goroutine helpers (`lo.NewTransaction`, `lo.Transaction`, `lo.ChannelDispatcher`, `lo.SliceToChannel`, `lo.ChannelToSlice`, `lo.Generator`, `lo.Buffer*`, `lo.FanIn`, `lo.FanOut`), plus `lo.Must*` (C02).
- Refactor collection loops in:
  - `internal/domain/service/reconciliation_service.go` (`groupLedger` → `lo.GroupBy`, `groupExternal` → `lo.GroupBy`, `unionRefs` → `lo.Union(lo.Keys(a), lo.Keys(b))` + `slices.Sort`).
  - `internal/domain/entity/tenant.go` and `internal/domain/service/tenant_onboarding.go` (infallible slice deduplication/filtering via `lo.Uniq`, `lo.Filter`, `lo.ContainsBy`).
  - `internal/application/workflow/saga.go` and `internal/application/workflow/compensate.go` (`byName` step index via `lo.KeyBy`).
  - `internal/infrastructure/database/postgres/repositories/{posting.go,search.go,account.go,entry.go,hold.go,ledger.go}` (`lo.UniqMap`, `lo.KeyBy`, and infallible `lo.Map` projections).
  - `internal/infrastructure/messaging/redpanda/topics.go` and `internal/infrastructure/egress/limiter.go` (infallible slice/map key projections via `lo.Map` / `lo.Keys`).
- `tasks/scripts/gate-check.sh`: update the G2 domain dependency check to allow exactly the `github.com/samber/lo` root package per `ADR-026`, rejecting `github.com/samber/lo/mutable`, `github.com/samber/lo/parallel`, and every other external import.
- `SPEC.md §2` and `docs/architecture/ADR-026-samber-lo-pure-collection-helpers.md`.

### Out of Scope

- Replacing loops whose bodies perform fallible `(T, error)` validation, checked integer arithmetic (`docs/ledger-core.md`), or cancellable `context.Context` I/O.
- Adopting `github.com/sourcegraph/conc` (explicitly rejected per `ADR-026`).
- `fx.ValidateApp` / `fxtest` standardization (`E09.2-T02`), `nilaway` (`E09.2-T03`), and `pyroscope-go` (`E09.2-T04`).

## Conflicts Resolved (2026-10-18)

- **C01 — `lo/mutable` in `depguard` allow lists vs. the ban in `AGENTS.md` / `go-conventions.md` / `clean-architecture-guide.md` / `SPEC.md` (CORRECTED by owner ruling, 2026-10-18).** The originally drafted epic E09.2-T01 Step 2, packet R02, and ADR-026 Decision 1 required `depguard` to *allow* `github.com/samber/lo/mutable` in `domain`, `application`, and `composition-roots`, which contradicted `AGENTS.md` ("Never import … `github.com/samber/lo/mutable`"), `docs/development/go-conventions.md` item 4, `docs/architecture/clean-architecture-guide.md §4`, and `SPEC.md §2`. An interim 2026-10-18 resolution kept the packet text; the repository owner then ruled that inclusion a drafting slip and that `github.com/samber/lo/mutable` is **strictly banned**: in-place mutation of shared slice backing arrays breaks value-object immutability, and only pure stateless root combinators were ever approved. R02 now removes the three allow entries and adds an explicit `deny` for `github.com/samber/lo/mutable` in all six rule sets; the same correction was applied to `tasks/scripts/gate-check.sh` G2, `test/unit/domain/guard_test.go`, `SPEC.md §2`, `docs/architecture/ADR-026-samber-lo-pure-collection-helpers.md`, the epic's E09.2-T01 steps/acceptance criteria, and the `tasks/tracking/GATES.md` G2 checklist line.
- **C02 — `lo.Must*` (RESOLVED by owner decision).** The epic's `forbidigo` regex omits `lo.Must*`, while `AGENTS.md` ("never call … `lo.Must*`"), `go-conventions.md` item 4 ("`lo.Must*` in non-test production code"), and the harness profile ban it. The owner approved adding `lo.Must`, `lo.Must0`…`lo.Must6` to the `forbidigo` ban on 2026-10-18 (strictly additive to `E09.2-T01-R03`; `forbidigo` has no per-file scoping, so the ban also applies to test code, which matches the repository's `require.NoError` test policy).
- **C03 — Epic line references are stale.** Epic Step 4 cites `reconciliation_service.go` lines 194–203/205–214/216–230 and `posting.go` lines 125–128 for the pre-refactor helpers; the current tree has them at `reconciliation_service.go` 318–393 and `posting.go` 145–195. The refactor targets the current helper bodies, not the line numbers.
- **C04 — `ledger.go` and `egress/limiter.go` have no infallible projection to convert.** The epic names `internal/infrastructure/database/postgres/repositories/ledger.go` for `lo.Map`; its row loop calls the fallible `models.LedgerToEntity(row) (entity.Ledger, error)` and must stay an explicit `for` loop per this packet's invariant. `internal/infrastructure/egress/limiter.go`'s only collection loop validates policies and rejects duplicates (fallible) and likewise stays explicit.
- **C05 — Tenant helpers prefer `slices` over `lo.*` (recorded decision).** The epic suggests `lo.Uniq`/`lo.ContainsBy`/`lo.Filter` for `internal/domain/entity/tenant.go` and `internal/domain/service/tenant_onboarding.go`. `AGENTS.md` and `go-conventions.md` item 2 require preferring an exact Go 1.27 `slices` equivalent (`slices.Contains`, `slices.ContainsFunc`) over `lo.Contains`/`lo.ContainsBy`; `internal/domain/entity/tenant.go` has no infallible slice loop at all (its loops are fallible per-rune/field validation, which the packet invariant keeps explicit).
- **C07 — G2 domain-import check precision (recorded decision).** The prepared `tasks/scripts/gate-check.sh` filtered `grep -v '^github.com/samber/lo'` over `go list -deps`, which still failed because `samber/lo` transitively pulls `golang.org/x/text`, and which would also have permitted a direct `github.com/samber/lo/parallel` import. The G2 check now inspects **direct** imports (`go list -f '{{range .Imports}}{{println .}}{{end}}'`), allows exactly the `github.com/samber/lo` root package (the `lo/mutable` exception was removed by the C01 correction), and still fails on any other external module (including a direct `golang.org/x/text` import) — matching `test/unit/domain/guard_test.go` and the GATES.md G2 wording.
- **C06 — Hermetic domain-import guard missing from the original file list (change-surface amendment).** `test/unit/domain/guard_test.go#TestDomainHasNoExternalImports` parses every non-test domain file and fails on any non-stdlib import, so it fails as soon as `internal/domain/service/reconciliation_service.go` imports `github.com/samber/lo` — making scenario S01 (`go test -race ./...`) unsatisfiable without updating it. The guard encodes the same rule as `tasks/scripts/gate-check.sh` G2, which this packet already owns and updates, so the amendment is mechanical: the guard now allows exactly the `github.com/samber/lo` root package per ADR-026 and still rejects `github.com/samber/lo/mutable`, `github.com/samber/lo/parallel`, and every other external module. Recorded here before editing the file (SDD §3.3.4).
- **C08 — Review round 1 hardening (2026-10-18, `tasks/reviews/E09.2-T01.md`).** CR-001/CR-002: `forbidigo` now also bans `lo.NewTransaction`, `lo.SliceToChannel`, `lo.ChannelToSlice`, and `lo.Generator`, and `depguard` denies the unapproved `github.com/samber/lo/it` package in all six rule sets (R02/R03 amended); S03 extended to probe them. CR-003 (aliasing/dot-import evasion) is **contested** — probes show `analyze-types: true` makes `forbidigo` resolve the canonical package name, so `mylo.Attempt` and dot-imported `Attempt` are rejected. CR-004: `DeriveTenantAlias` restores a single pre-indexed set via `lo.Keyify` (added to the ADR-026 approved combinator list) instead of repeated `slices.Contains` scans. `docs/architecture/README.md` and the reply section of `tasks/reviews/E09.2-T01.md` are added to `Owns` for the ADR-026 index row (`Proposed` → `Accepted`, review SDD/Docs Gap) and the implementer replies. ## Invariants and Failure Semantics

- **Money & Accounting Invariants Unchanged**: Checked integer minor-unit arithmetic (`docs/ledger-core.md`) and fallible `(T, error)` validation loops must remain explicit `for` loops with immediate error return.
- **Deterministic Map Iteration**: Whenever `lo.Keys`, `lo.Values`, or `lo.Union` extracts a slice from a Go `map`, sort the resulting slice with `slices.Sort` / `slices.SortFunc` if downstream callers depend on deterministic ordering (such as `unionRefs` in `reconciliation_service.go`).
- **Concurrency Containment**: `github.com/samber/lo/parallel` is forbidden across all packages; all goroutines must use `internal/shared/kernel/safe` or `golang.org/x/sync/errgroup`.
