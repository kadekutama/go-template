## Objective

Ship Journal grouping with scope validation, the Period open→close→reopen lifecycle with caller-verified close preconditions, sub-ledger partitioning helpers, and evidence-gated opening-balance validation — stdlib-only, emitting `period.opened/closed/reopened.v1`.

## Scope

### In Scope

- `internal/domain/entity/journal.go`: `Journal` (ID, tenant/ledger/period scope, posting IDs, description, metadata) + `NewJournal` validating uniform posting scope (mixed tenants/ledgers fail) and ≥1 posting.
- `internal/domain/entity/period.go`: `PeriodData` record (ID, tenant/ledger, start/end, timezone, OPEN/CLOSED status) + `Validate()` (start < end, scope present).
- `internal/domain/aggregate/period.go`: `Period` aggregate with `OpenPeriod`, `Close` (requires caller-passed unresolved workflow/break counts; blocked when > 0), `Reopen` (privileged: approver + reason required), versioning, and uncommitted `period.opened/closed/reopened.v1` events.
- `internal/domain/service/period_service.go`: `SubLedgerKey{tenant,ledger,asset}` + `BelongsToSubLedger` (entry membership via account set), `ValidateOpeningBalance` (open period + balanced per-asset lines + evidence/approval reference; never writes balances).
- Lifecycle, scope-mixing, blocked-close, approval, opening-balance, and sub-ledger tests.

### Out of Scope

- Posting into periods (E02-T04 constructs; E07 checks `EffectiveAt` against the open period at commit).
- Reconciliation matching/breaks (E04), maker-checker approval workflows (E04-T02; `Reopen` takes an explicit approver string only).
- Balance import as committed postings (E03/E06 construct via `ConstructPosting` after this validation).

## Requirements

| ID | Requirement | Priority |
|----|-------------|----------|
| E02-T05-R01 | `NewJournal` MUST require ≥1 posting and uniform tenant+ledger across journal and all postings; mixed tenants/ledgers MUST fail. | must |
| E02-T05-R02 | `PeriodData` MUST require non-empty scope, start < end, and known OPEN/CLOSED status. | must |
| E02-T05-R03 | `Close` MUST fail with `PERIOD_CLOSE_BLOCKED` when caller-passed unresolved workflow/break counts are > 0; close on CLOSED MUST fail `PERIOD_CLOSED`. | must |
| E02-T05-R04 | `Reopen` MUST require non-empty approver + reason (`PERIOD_REOPEN_APPROVAL`); reopen on OPEN MUST fail. | must |
| E02-T05-R05 | Open/Close/Reopen MUST emit exactly `period.opened/closed/reopened.v1` with matching IDs and bump `Version` from 1. | must |
| E02-T05-R06 | `ValidateOpeningBalance` MUST require an OPEN period, per-asset balanced positive lines, and non-empty evidence source/URI + approver; it MUST NOT construct postings or write balances. | must |
| E02-T05-R07 | `BelongsToSubLedger` MUST partition per tenant/ledger/asset without summing unlike assets. | must |
| E02-T05-R08 | New code MUST import only stdlib + `internal/domain/...`. | must |

## Executable Scenarios

| ID | Given | When | Then |
|----|-------|------|------|
| E02-T05-S01 | Journal + same-scope postings | `NewJournal` | Journal with posting IDs; no error. |
| E02-T05-S02 | Postings from two tenants (or ledgers) | `NewJournal` | Scope-mismatch error; no journal. |
| E02-T05-S03 | OPEN period, zero pending counts | `Close` | CLOSED, Version 2, `period.closed.v1`. |
| E02-T05-S04 | OPEN period, 2 unresolved breaks | `Close` | `PERIOD_CLOSE_BLOCKED`; still OPEN. |
| E02-T05-S05 | CLOSED period + approver/reason | `Reopen` → `Close` again | OPEN then CLOSED; `reopened` then `closed` events. |
| E02-T05-S06 | OPEN period, balanced lines, evidence+approver | `ValidateOpeningBalance` | nil (no posting constructed). |
| E02-T05-S07 | CLOSED period / missing evidence / unbalanced lines | `ValidateOpeningBalance` | `PERIOD_CLOSED` / `EVIDENCE_REQUIRED` / `UNBALANCED_TRANSACTION`. |
| E02-T05-S08 | Entries across USD/EUR + sub-ledger keys | `BelongsToSubLedger` | Per-asset membership only; unlike assets never match. |

## Invariants and Failure Semantics

- Domain stays pure: close preconditions are caller-verified counts (E04/E06 supply them); reopen approval is a string pair (workflow lives in E04).
- Opening-balance import records source/evidence/actor via `EvidenceRef`; the balanced posting itself is built downstream.
- Errors carry stable codes; panics forbidden.
