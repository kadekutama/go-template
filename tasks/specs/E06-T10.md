## Objective

Meter billable application events into per-tenant daily usage (idempotent on event ID) and export invoice-ready CSV consumed by the fee-revenue report and external billing providers.

## Scope

### In Scope

- `internal/application/service/billing_service.go`: `BillingService` + `UsageStore` (consumer-owned, E07-T10 implements) — `Record` (validated, idempotent append), `DayTotals`, `ExportCSV` (usage lines + totals).
- `internal/application/dto/billing.go`: usage line/export edge shapes.
- Tests: replayed events never double-count, export matches hand-computed totals, invalid inputs rejected.

### Out of Scope

- Actual charging (external billing provider fed by webhook/export), persistence schema (E07-T10), price books/currency conversion (provider-side), saga integration (E06-T07 consumes summaries only).

## Requirements

| ID | Requirement | Priority |
|----|-------------|----------|
| E06-T10-R01 | `Record` MUST validate tenant/event/kind/quantity/day and append idempotently: replayed event IDs MUST NOT double-count. | must |
| E06-T10-R02 | Usage MUST bucket per tenant + UTC day + kind for the four billable kinds (transactions-posted, api-calls, payouts, reports-generated). | must |
| E06-T10-R03 | `ExportCSV` MUST render deterministic usage lines plus a TOTAL line consumable by the fee-revenue report; bad day ranges MUST fail. | must |

## Executable Scenarios

| ID | Given | When | Then |
|----|-------|------|------|
| E06-T10-S01 | One event | Record twice | applied once, totals count once |
| E06-T10-S02 | Events across 2 days × 2 kinds | ExportCSV | Lines + TOTAL match hand computation |
| E06-T10-S03 | Unknown kind / zero quantity / bad day | Record/Export | Validation errors, nothing stored |

## Interfaces and Data

```go
// UsageKind string {"transactions-posted","api-calls","payouts","reports-generated"}
// UsageEvent{EventID, TenantID, Kind, Quantity, OccurredAt}
// DailyUsage{TenantID, Day, Kind, Quantity}
// UsageStore{AppendEvent(ctx, UsageEvent) (bool, error); DayTotals(ctx, tenant, day) (map[UsageKind]int64, error); PeriodLines(ctx, tenant, fromDay, toDay) ([]DailyUsage, error)}
// BillingService{Store UsageStore} (Record, DayTotals, ExportCSV)
// UsageLineDTO{Tenant, Day, Kind, Quantity}; BillingExportDTO{Lines, Total}
```

## Invariants and Failure Semantics

- Append-only metering: no updates, no deletes; corrections are new events (documented for E07).
- Day buckets derive from UTC event date; clock skew lands in the event's day, never adjusted.
- Export is a pure read over stored lines; rendering never mutates.
