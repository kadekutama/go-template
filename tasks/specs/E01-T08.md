# Task Specification: E01-T08 — Resilience primitives (breaker, timeout, retry)

**Task:** E01-T08  
**Spec Status:** ready  
**Author:** opencode-agent

**Last Updated:** 2026-09-14

## Objective

Give every outbound provider one reviewable resilience policy (breaker +
timeout + classified retry) with a hard rule: non-idempotent operations never
retry without a durable/provider idempotency key.

## Scope

### In Scope

- `internal/shared/kernel/resilience/{breaker.go,policy.go}`: `Breaker` port
  (`Execute` with operation name + idempotency key), `RetryPolicy`, error
  classification (`Retryable`/`Permanent`/`Unknown`), context-deadline
  propagation, cancellation never retried.
- `internal/infrastructure/resilience/{gobreaker.go,retry.go}`: gobreaker
  adapter (closed/open/half-open, metrics hook, bounded backoff) + retry
  executor with injectable clock/sleep for deterministic tests.
- Deterministic tests: transitions with fixed clock, timeout, cancellation,
  retry exhaustion, no-blind-retry proof.

### Out of Scope

- Provider adapters themselves (E10 consumes the ports; gobreaker import stays
  in the adapter package only).
- Metrics backend (hook interface; E15 wires Prometheus).

## Requirements

| E01-T08-R01 | Breaker MUST transition closed→open→half-open and recover; unit-proven with fixed clock. | must |

## Executable Scenarios

| ID | Given | When | Then |
|----|-------|------|------|
| E01-T08-S01 | Breaker, failing fn | Failures hit threshold | Opens; fast-fails without calling fn. |
| E01-T08-S02 | Open breaker, clock advanced past timeout | Call arrives | Half-open probe; success closes. |
| E01-T08-S03 | Retryable fn failing twice then succeeding (max 3) | Execute with key | 3 calls, success returned. |
| E01-T08-S04 | Non-idempotent fn failing retryably, no key | Execute | 1 call, error returned, no retry. |
| E01-T08-S05 | Cancelled context | Execute | fn never called (or aborted), context error, no retry. |
| E01-T08-S06 | Always-failing retryable fn | Execute with key, max 3 | 3 calls then exhaustion error. |

## Interfaces and Data

`resilience.Breaker{Execute, State}`, `resilience.RetryPolicy{MaxAttempts,
InitialBackoff, MaxBackoff, Multiplier}`, `resilience.Class{Retryable,
Permanent, Unknown}`, `resilience.Classifier func(error) Class`,
`resilience.RetryableError/PermanentError` wrappers, adapter
`gobreaker.New(name, settings, hooks)` + `retry.Execute(ctx, clock, sleep,
policy, key, idempotent, classifier, fn)`.

## Invariants and Failure Semantics

- Timeouts via context deadlines (caller-owned); breaker counts timeouts as failures.
- Unknown class + idempotency key MAY retry (bounded); without key treats as non-idempotent.
- Half-open allows one probe (gobreaker MaxRequests=1).
