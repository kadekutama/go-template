## Objective

Ship immutable double-entry Posting/Entry construction with per-asset balance enforcement and posting-side account checks, plus the idempotent Hold state machine — stdlib-only, with `transaction.posted/reversed` emission.

## Scope

### In Scope

- `internal/domain/entity/entry.go`: `Entry` (ID, PostingID, AccountID, Side, positive AmountMinor, AssetCode, AccountSeq ≥ 1) + `Validate()`; no `balance_after`, no signed amounts.
- `internal/domain/entity/posting.go`: `PostingData` record + structural `Validate()` (≥2 entries, per-entry validity).
- `internal/domain/entity/hold.go`: `HoldData` (ID, tenant/ledger/account/asset scope, positive amount, kind, state ACTIVE/CAPTURED/RELEASED/EXPIRED, expiry, version) + `Validate()`.
- `internal/domain/aggregate/posting.go`: immutable `Posting` + `ConstructPosting` (positive entries, account existence/scope/asset/status checks against caller-supplied accounts, per-asset debit=credit, reversal linkage) + `ReversePosting` (opposite-side linked posting) + `transaction.posted/reversed.v1` uncommitted events.
- `internal/domain/aggregate/hold.go`: `Hold` with idempotent `Capture`/`Release`/`Expire` (expiry-gated, versioned, no events — balance effects publish via `account.balance.changed` downstream).
- `HoldID` typed ID appended to `valueobject/ids.go` (T02 coordination) + tests.
- Transition-table, immutability-reflection, per-asset-balance, FX-lots, and reversal tests.

### Out of Scope

- Durable idempotency records, deterministic locking, checkpoints, outbox atomicity (E07 owns the posting transaction).
- Posting-template authorization (E02-T07 `PostingTemplateAllowed` consumes Posting).
- Balance computation and `account.balance.changed` publication (E06/E07).
- Hold kinds beyond an explicit non-empty kind string (E03 workflows specialize).

## Requirements

| ID | Requirement | Priority |
|----|-------------|----------|
| E02-T04-R01 | `ConstructPosting` MUST require ≥2 entries, every entry strictly positive with `AccountSeq ≥ 1`, and MUST reject signed/zero amounts (`INVALID_ENTRY_AMOUNT`). | must |
| E02-T04-R02 | For each asset code independently, total debits MUST equal total credits or construction MUST fail with `UNBALANCED_TRANSACTION` carrying both totals per asset in details. | must |
| E02-T04-R03 | Every entry account MUST exist in the caller-supplied set, share the posting tenant+ledger, match the entry asset, and be ACTIVE (`ACCOUNT_FROZEN`/`ACCOUNT_CLOSED` otherwise). | must |
| E02-T04-R04 | Cross-currency postings MUST carry independently balanced lots per asset (FX linkage via metadata, e.g. `fx_trade_id`); mixed lots MUST fail R02. | must |
| E02-T04-R05 | A posting with `ReversalOf` MUST carry a non-empty reason; `ReversePosting` MUST take an `IDGenerator` for mirrored entry IDs (nil fails closed), build opposite-side entries, set `ReversalOf`, and emit `transaction.reversed.v1`. | must |
| E02-T04-R06 | Posting MUST expose no mutator (reflection test); correction is a new linked posting only. | must |
| E02-T04-R07 | Hold `Capture`/`Release`/`Expire` MUST be idempotent on repeat of the reached terminal state, MUST reject conflicting transitions, MUST gate on expiry (`HOLD_EXPIRED`/`HOLD_NOT_EXPIRED`), and MUST bump `Version` only on state change. | must |
| E02-T04-R08 | Holds MUST affect no entry set: they are not entries and emit no posting events. | must |
| E02-T04-R09 | New code MUST import only stdlib + `internal/domain/...`. | must |

## Executable Scenarios

| ID | Given | When | Then |
|----|-------|------|------|
| E02-T04-S01 | Two ACTIVE same-ledger accounts + balanced USD entries | `ConstructPosting` | Posting returned + one `transaction.posted.v1` with complete entries. |
| E02-T04-S02 | USD debits 100 vs credits 90 | `ConstructPosting` | `UNBALANCED_TRANSACTION` with debit=100/credit=90 details. |
| E02-T04-S03 | EUR lot balanced + USD lot balanced, `fx_trade_id` set | `ConstructPosting` | Passes (independent lots). |
| E02-T04-S04 | Entry on a FROZEN (then CLOSED) account | `ConstructPosting` | `ACCOUNT_FROZEN` (then `ACCOUNT_CLOSED`). |
| E02-T04-S05 | Committed posting + reason | `ReversePosting` | Opposite sides, `ReversalOf` set, `transaction.reversed.v1`. |
| E02-T04-S06 | Reflection over Posting | Mutator search | No `Set*/Update*/Delete*` methods; no exported mutable fields. |
| E02-T04-S07 | ACTIVE hold | `Capture` twice / `Release` after capture / `Expire` after capture | nil, nil (idempotent), error. |
| E02-T04-S08 | ACTIVE hold past expiry / before expiry | `Expire` / `Capture` after expiry | EXPIRED + nil repeat; `HOLD_EXPIRED` on late capture. |

## Interfaces and Data

```go
// entity: Entry{...} + Validate(); PostingData{ID,TenantID,LedgerID,Operation,
//   ExternalReference,Description,Entries,EffectiveAt,RecordedAt,ReversalOf *PostingID,
//   Reason,Metadata} + Validate(); HoldData{...} + Validate(); HoldState consts.
// aggregate: Posting (unexported state, accessors, Entries() copy, UncommittedEvents)
//   ConstructPosting(PostingParams{IDs, scope, operation, entries, accounts map[AccountID]AccountData,
//     effective/recorded times, reversal, reason, metadata, eventID}) (Posting, error)
//   ReversePosting(original Posting, params{NewID, Reason, Actor, EventID, At, IDGen}) (Posting, error)
//   Hold{...} Capture()/Release()/Expire(at) error; State()/Version()/Record()
```

- No wire/migration/config change. `RecordedAt` is caller-supplied (server clock in app layer).

## Invariants and Failure Semantics

- Accepted postings have no pending/failed/voided state and expose no mutator.
- `balance_after` storage forbidden; signed amounts forbidden.
- Reversal entries use the opposite side and retain reason + actor.
- Hold expiry is time-compared with caller-supplied `at` (UTC); clock injection stays in app layer.
- Errors carry stable codes; panics forbidden.
