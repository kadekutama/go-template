## Findings

### CR-010 — OpenBao `DBMount` silent default and `ErrSecretNotFound` sentinel conflation [Low] [Confirmed]
- **Location:** `internal/infrastructure/secrets/openbao/client.go:48-67` (`NewStore`),
  `client.go:117-162` (`fetchKV`)
- **Issue:** `DBMount` is tagged `validate:"required,max=64"` but `NewStore` never runs the
  validator and substitutes `dbMount = "database"` when empty — a silent default. In the
  same file, `fetchKV` maps transport errors, non-404 HTTP statuses, and decode failures
  all to `ErrSecretNotFound`.
- **Why it matters:** An unconfigured mount is a value no operator chose (against the
  zero-defaults doctrine the same round introduced, ADR-021 — Proposed); during an OpenBao
  outage at boot, the error says "secret not found: <name> status 503" under a not-found
  sentinel, so callers cannot distinguish a misconfiguration from an outage without
  parsing messages. Both paths fail closed.
- **Evidence:** `NewStore`'s manual checks cover Address/Token/KVMount/HTTP/Clock/DefaultTTL
  but not DBMount; every `fetchKV` error path wraps `ErrSecretNotFound` (including
  `resp.StatusCode != 200` and `Unmarshal` failures).
- **Plan violation:** E09-T05-R01 partial (miss MUST fail with the path in the error — it
  does, but the sentinel overreaches); ADR-021 §1 (proposed).
- **Expected behavior:** Empty `DBMount` fails construction; transient errors carry a
  distinct sentinel (or wrap) from the not-found path while still failing closed.
- **Recommended fix:** Reject empty `DBMount` in `NewStore` (per ADR-021); introduce a
  distinct `ErrSecretUnavailable` (or wrap a transport-class error) for non-404 failures.
- **Verification:** Constructor case with empty `DBMount` → `ErrConfigRequired`; httpmock
  case with HTTP 503 asserting the error is *not* `ErrSecretNotFound`.
