## Objective

Deliver Valkey Redlock coordination for cron/reconciliation duplicate-work suppression behind `port.DistributedLock`, with PostgreSQL remaining the money-safety boundary.

## Scope

### In Scope

- `internal/infrastructure/lock/redlock.go`: acquire (SET NX PX, TTL 30s default), release/refresh (GET+DEL/GET+SET token guard), fencing token; `Refresh` fails with `ErrLockLost` when the lease is gone or taken over.
- `internal/infrastructure/lock/guard.go`: `WithLock` running `fn` under the lease with a background renewal loop (interval = explicit `RefreshInterval` or ttl/3, floored at 1s), contention/release hooks, typed errors, and documented error precedence.
- Implements `port.DistributedLock` + `port.Lock`.

### Out of Scope

- Ledger locking/uniqueness (PostgreSQL owns), rate limiting (E08-T07), scheduler jobs (E14), cache values (E08-T01).

## Requirements

| ID | Requirement | Priority |
|----|-------------|----------|
| E08-T02-R01 | Acquire MUST use atomic SET NX PX with a random token; a held key MUST fail fast with a typed contention error (`ErrLockHeld`). | must |
| E08-T02-R02 | `Lock.Refresh` MUST extend only when the caller still holds the token and MUST fail with `ErrLockLost` (wrapping the cause) when the lease is expired, missing, or taken over. | must |
| E08-T02-R03 | `Lock.Release` MUST be idempotent and MUST only delete when the token matches (a stale holder never frees the current holder's lease). | must |
| E08-T02-R04 | `WithLock` MUST auto-renew held leases for the duration of `fn` (watchdog goroutine), release on completion/failure — including caller cancellation (release runs on `Background`) — and MUST surface contention via `OnContended` + `ErrLockHeld`. | must |
| E08-T02-R05 | A renewal panic MUST be contained via `safe.Group` (logged with stack, delivered to the guard) instead of crashing the process; lease loss MUST cancel `fn`'s context. | must |
| E08-T02-R06 | Error precedence MUST be explicit: the work's own error wins; lease loss (wrapping `ErrLockLost`) takes precedence over the derived `context.Canceled` it caused. | must |
| E08-T02-R07 | Valkey loss/expiry MUST NOT duplicate a posting or permit overspend: protected durable writes MUST validate lease/fencing or an idempotent run key. | must |

## Executable Scenarios

| ID | Given | When | Then |
|----|-------|------|------|
| E08-T02-S01 | Free key | Two contenders `Acquire` concurrently | Exactly one holds; other gets contention error |
| E08-T02-S02 | Held lease, holder slow | `Refresh` before expiry then after simulated loss | First extends, second fails with `ErrLockLost` |
| E08-T02-S03 | Released/expired lease | `Release` twice; stale holder releases after takeover | All succeed and the current holder keeps the lease (never stolen) |
| E08-T02-S04 | Contended cron run | `WithLock` around Valkey `SetNX` durable effect key | Exactly one effect commits; losers get `ErrLockHeld` |
| E08-T02-S05 | Lease lost mid-run | Renewal loop refresh fails | `fn`'s context is cancelled and `WithLock` returns the `ErrLockLost` chain, preferring it over the derived `context.Canceled` |
| E08-T02-S06 | Renewal goroutine panics | Watchdog panics | Panic contained as an error (logged with stack), `fn` cancelled, no process crash |
| E08-T02-S07 | Caller cancels while `fn` runs | Context cancelled | `fn` sees cancellation; the lease is still released on `Background` |

```go
// func WithLock(ctx, params GuardParams, tenant, key string, ttl time.Duration, fn func(ctx) error) error
// Sentinel errors: ErrLockHeld, ErrLockLost, ErrClientRequired, ErrNotInitialized, ErrLeaseNotInit,
//                 ErrKeySegmentRequired/TooLong/Colon, ErrTTLPositive
// Release is token-compared and idempotent; Refresh extends only while the token matches.
// Known limit: compare-then-write is non-atomic (no Lua per single-script guard); safe for
// coordination-only use because durable writes validate fencing/run keys (tested: release never steals).
```

## Invariants and Failure Semantics

- Locks coordinate; database constraints serialize money.
- TTL 30s default; the guard renews at ttl/3 (floored at 1s) while `fn` runs; a lost lease cancels `fn`.
- `WithLock` error precedence: work error wins; `ErrLockLost` wins over the derived `context.Canceled`; renewal panic surfaces as an error.
- Context cancel aborts acquire/refresh; never blocks longer than ctx deadline. Release always runs on `Background`.
- Release on a taken-over lease is a no-op; refresh on a lost lease returns `ErrLockLost`.
