# Task Specification: E01-T04 — Structured logging port + slog adapter

**Task:** E01-T04  
**Spec Status:** ready  
**Author:** opencode-agent  
**Reviewer:** opencode-agent (self-review recorded per `tasks/SDD.md §3.1`; mechanical logging port, no financial/cryptographic/migration behavior)  
**Last Updated:** 2026-09-14

## Objective

Give domain/application a backend-free `Logger` port with correlation context,
backed by zerolog JSON output (ADR-012, superseding ADR-010's slog default),
so every later component logs uniformly and the backend stays swappable via
one fx line.

## Scope

### In Scope

- `internal/shared/kernel/log/{logger.go,context.go}`: UNCHANGED port shape,
  extended to all 7 zerolog levels (Trace/Debug/Info/Warn/Error/Panic/Fatal —
  owner directive 2026-09-14). Panic logs then panics with msg (recoverable via
  `safe.Go`); Fatal logs then exits 1 (stub-able in tests, unrecoverable by design).
- `internal/infrastructure/logging/{zerolog_adapter.go,config.go}`: zerolog
  adapter (replaces `slog_adapter.go`, deleted). JSON output, RFC3339Nano UTC
  timestamps, config-driven level, `Discard()` test logger. zerolog shape
  globals set once under `sync.Once` in the constructor (sanctioned, documented).
- `internal/infrastructure/logging/fx_logger.go` (audit fix 2026-09-17):
  `fxevent.Logger` over the kernel port so fx framework events flow through
  zerolog instead of `fx.NopLogger`; lifecycle milestones at Info, routine
  wiring at Debug, hook/supply/invoke failures at Error.
- fx provider updated to the zerolog constructor (same single call site).

### Out of Scope

- Middleware injection of request IDs (E11 consumes the context helpers).
- Alternative backends (adapter seam documented; swap = new file + one fx line).

## Requirements

| ID | Requirement | Priority |
|----|-------------|----------|
| E01-T04-R01 | `Logger` MUST offer Trace/Debug/Info/Warn/Error/Panic/Fatal + `With(args...) Logger`; context helpers MUST carry request_id/trace_id/tenant_id/user_id. | must |
| E01-T04-R02 | A log line MUST contain `request_id`/`trace_id` when present in context (unit-proven). | must |
| E01-T04-R03 | zerolog adapter MUST emit JSON with RFC3339Nano UTC timestamps and a config-driven level; tests use the real adapter via `New(w, cfg)` to catch formatting issues early. | must |
| E01-T04-R04 | Swapping zerolog MUST require only a new adapter + one fx line (review-proven by the single-call-site provider). | must |
| E01-T04-R05 | `Panic` MUST emit the line then panic with msg (recoverable, test-proven); `Fatal` MUST emit the line then exit 1 via a stub-able exit func (test-proven without exiting). | must |
| E01-T04-R06 | fx framework events MUST route through the kernel `Logger` via `logging.NewFxLogger` (milestones Info, wiring Debug, failures Error); production mains MUST NOT use `fx.NopLogger`. | must |

## Executable Scenarios

| ID | Given | When | Then |
|----|-------|------|------|
| E01-T04-S01 | Context with request_id + trace_id | Info called with buffer-backed logger | Output JSON contains both IDs. |
| E01-T04-S02 | `With("k","v")` child logger | Warn called | Child line contains k/v; parent unaffected. |
| E01-T04-S03 | Level=error config | Debug + Error called | Only Error emitted. |
| E01-T04-S04 | fx graph (ValidateApp) | Infrastructure module validated | Provider resolves (test). |
| E01-T04-S05 | Level=trace config vs level=info config | Trace called | Emitted iff trace enabled. |
| E01-T04-S06 | `Panic` inside `safe.Go` | It runs | Line emitted; panic recovered with msg. |
| E01-T04-S07 | `Fatal` with stubbed exit | It runs | Line emitted; exit called once with code 1; process alive. |
| E01-T04-S08 | fx lifecycle events (`Started`, `Provided`, `OnStartExecuted` with/without error) | `LogEvent` called on buffer-backed adapter | Milestones at Info, wiring at Debug, failures at Error with the error attached. |

## Interfaces and Data

`log.Logger` interface; `log.WithContext/FromContext/WithRequestID/...`
helpers; `logging.Config{Level}`; `logging.New(w, cfg) Logger`;
`logging.NewFxLogger(inner Logger) fxevent.Logger`;
fx provider `ProvideLogger`.

## Invariants and Failure Semantics

- Domain/application import only the port, never the adapter.
- Logging never fails the caller (no error returns); misconfigured level falls
  back to info (fail-open for observability, never for money).
