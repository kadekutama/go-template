## Objective

Ship pure erasure/portability rules: personal data crypto-shredded with tombstone + audit while ledger sums stay intact, and export bundles that round-trip through validation.

## Scope

### In Scope

- `internal/domain/service/gdpr_service.go`: `ClassifyField`, `ErasePII`, `BuildExportBundle`, `ValidateExportBundle`.

### Out of Scope

- Key destruction plumbing, persistence deletes, API/handlers (E07/E06/E11); report rendering (E18); legal-hold workflow engine (future).

## Requirements

| ID | Requirement | Priority |
|----|-------------|----------|
| E04-T04-R01 | Field classification MUST treat names/emails/metadata descriptors as erasable PII and amounts/entries/posting IDs/audit facts as retained ledger facts. | must |
| E04-T04-R02 | Erasure MUST shred PII values (replace with tombstone marker), write a tombstone record + audit entry, sort shredded fields deterministically, block under legal hold (`LEGAL_HOLD_ACTIVE`), and MUST preserve double-entry sums verified by `VerifyLedgerSumsPreserved`. | must |
| E04-T04-R03 | The `pii.erased.v1` payload MUST contain only IDs/hashes/timestamps, never erased values; `DetectErasedValueLeak` MUST catch exact and substring leaks (`ERASED_VALUE_LEAKED` if violated). Tombstone uses full SHA256 hex. | must |
| E04-T04-R04 | Export bundles MUST include accounts/transactions/entries in JSON/CSV shapes and MUST round-trip through `ValidateExportBundle`. | must |
| E04-T04-R05 | Every erasure MUST produce exactly one audit entry (`AUDIT_REQUIRED` otherwise). | must |
| E04-T04-R06 | New code MUST import only stdlib + `internal/domain/...`. | must |

## Invariants and Failure Semantics

- Erasure never deletes postings/entries or rewrites amounts. Stable codes: `FIELD_CLASS_UNKNOWN`, `AUDIT_REQUIRED`, `ERASED_VALUE_LEAKED`, `EXPORT_INVALID`.
- Tombstone marker is the constant `REDACTED:<sha256(field)>`; raw values never persisted in result maps.
