## Objective

Collapse concurrent identical cacheable reads into one provider call per process with `golang.org/x/sync/singleflight`, without introducing cross-node coordination or touching money-moving paths.

## Scope

### In Scope

- `internal/infrastructure/cache/coalesce/singleflight.go`: narrow `Coalescer{Do(ctx, CoalesceKey, fn)}` over `singleflight.Group.DoChan`, independently cancellable waiters, a credential-free service-owned shared-work context with hard timeout, cloned results, and no retained results/errors after completion.
- `go.mod`: promote `golang.org/x/sync` from indirect to direct.
- `SPEC.md §2`: record the exact `golang.org/x/sync v0.23.0` dependency pin.
- Explicit cacheable-read enum allow-list (initial consumer: FX rate reads); keys include provider + tenant/authorization scope + non-PII request identity digest; money-moving operations are rejected by validation and differing scopes form distinct in-flight keys.
- Deterministic unit tests: 50-way collapse, error non-retention, first-caller and waiter cancellation isolation, shared timeout, and mutable-byte isolation.

### Out of Scope

- Distributed (Valkey) coalescing — deferred until duplicate provider load is measured after the cache and worker paths are in use.
- Hybrid engine semantics changes (`internal/infrastructure/cache/hybrid/**` read-only coordination).
- Egress limiter behavior (E09.1-T03) and scheduler/UI work (E09.1-T01/T02).

## Requirements

| ID | Requirement | Priority |
|----|-------------|----------|
| E09.1-T04-R01 | 50 concurrent `Do` calls with the same valid key MUST execute `fn` exactly once and return byte-equal, independently owned slices to all non-canceled waiters. | must |
| E09.1-T04-R02 | Results and errors MUST be shared only while the call is in flight; after completion, the next `Do` MUST execute `fn` again. | must |
| E09.1-T04-R03 | Cancellation of the first caller or any waiter MUST NOT cancel shared work needed by other waiters. Shared work MUST derive its context from the service-owned `BaseContext` with a configured hard timeout, so service-shutdown cancellation still propagates; `fn` MUST honor either cancellation. A waiter MUST return on its own context cancellation or when the shared context ends. | must |
| E09.1-T04-R04 | Keys MUST include provider + tenant/authorization scope + non-PII request identity; empty fields and non-allow-listed operation kinds MUST fail before `fn`. | must |
| E09.1-T04-R05 | Caller mutation of one returned `[]byte` MUST NOT change another caller’s result. | must |
| E09.1-T04-R06 | Identical request digests with different provider or tenant/authorization scope MUST NOT share an in-flight result. | must |
| E09.1-T04-R07 | `go.mod` MUST require `golang.org/x/sync v0.23.0` as a direct dependency, and `SPEC.md §2` MUST record that exact pin. | must |

## Executable Scenarios

| ID | Given | When | Then |
|----|-------|------|------|
| E09.1-T04-S01 | 50 goroutines, same valid key, `fn` counts invocations | Concurrent `Do` | `fn` count == 1; all active callers receive equal bytes on separate backing arrays |
| E09.1-T04-S02 | `fn` returns error or a prior call has completed | Two sequential `Do` calls | Both calls execute `fn`; error/result is not retained after completion |
| E09.1-T04-S03 | First caller cancels while four other waiters remain | Shared operation in flight | First caller gets context error; remaining callers receive result; `fn` count == 1 |
| E09.1-T04-S04 | Empty key field, unknown kind, or money-moving kind | `Do` | Typed rejection before any `fn` execution |
| E09.1-T04-S05 | Context-aware shared operation waits past configured timeout | `Do` | Shared context is canceled at the bound; active waiters receive deadline exceeded and the cooperative `fn` exits |
| E09.1-T04-S06 | Same request digest with two different tenant/authorization scopes | Concurrent `Do` calls | `fn` runs once per scope; no cross-scope result sharing |
| E09.1-T04-S07 | Service-owned `BaseContext` is canceled while shared work is active | Cancel the service context | Cooperative `fn` exits; remaining waiters receive the shared context cancellation; no work survives service shutdown |

## Interfaces and Data

```go
// CoalesceParams{BaseContext context.Context, SharedTimeout time.Duration}
// BaseContext is service-owned and MUST NOT contain request credentials/identity.
// NewCoalescer(...) (*Coalescer, error)
// func (c *Coalescer) Do(ctx context.Context, key CoalesceKey, fn func(ctx context.Context) ([]byte, error)) ([]byte, error)
// type CoalesceKey struct { Provider, Scope, RequestDigest string; Kind CacheableReadKind }
// Kind is a closed enum (initial value: FXRate); unknown values are rejected.
// Shared work uses context.WithTimeout(BaseContext, SharedTimeout).
// Caller ctx controls only that caller's wait; BaseContext cancellation (e.g. service shutdown) cancels shared work.
// E10-T02 call order: Coalescer.Do(cache lookup -> on miss EgressLimiter/Retry/Breaker/Doer -> cache set).
```

## Invariants and Failure Semantics

- Read-only optimization: never authorizes spending, never establishes uniqueness; cache entries remain hints per the hybrid contract.
- Same parameters ≠ same intent: financial intent is out of scope for this primitive by type-level allow-listing, not by reviewer vigilance.
- Shared work MUST NOT carry request-specific credentials; authorization/tenant scope is part of the validated key. Each caller gets an independently mutable copy of response bytes.
- The shared callback MUST be context-cooperative; Go cannot forcibly terminate a function that ignores its context.
- The service-owned base context MUST be the parent of shared work (not wrapped in `context.WithoutCancel`); graceful shutdown cancels active shared operations while an individual request cancellation does not.
- No cross-process state; no Valkey keys introduced by this task.
