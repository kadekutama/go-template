# Task Specification: E03-T06 — Payment methods, settlement batches, returns, linking

**Task:** E03-T06
**Spec Status:** ready
**Author:** opencode-agent
**Reviewer:** repo-owner
**Last Updated:** 2026-09-14

## Objective

Ship payment-method registry, workflow state machine, return-code catalog with dispositions, payment linking, settlement-batch identity, and OUTCOME_UNKNOWN timeout rule.

## Scope

### In Scope

- `internal/domain/valueobject/payment_method.go`: ACH/Wire/RTP/Card/Crypto/Wallet + capabilities (push/pull, lag, reversible).
- `internal/domain/valueobject/payment_status.go`: REQUIRES_METHOD/ACTION → AUTHORIZED → CAPTURED → PENDING_SETTLEMENT → SETTLED / FAILED / RETURNED.
- `internal/domain/valueobject/return_code.go`: ACH R-code subset + card-decline mapping → auto-reversal vs manual-review.
- `internal/domain/service/payment_service.go`: method checks, irreversibility rule, timeout→OUTCOME_UNKNOWN with status-lookup-before-retry, duplicate-delivery idempotency.
- `internal/domain/entity/payment_link.go`, `settlement_batch.go`, `provider_object_link.go`: link uniqueness, batch totals/trace retention.

### Out of Scope

- Provider HTTP adapters (E10); persistence schema (E07 beyond port-shaped retention).

## Normative Inputs

- `tasks/epics/E03-money-movement.md#E03-T06` for the backlog boundary.
- `docs/ledger-core.md §7–§8` (OUTCOME_UNKNOWN, idempotent keys, no blind retry).
- `docs/money-flow.md §5`, `docs/domain-events.md §3.4`.

## Requirements

| ID | Requirement | Priority |
|----|-------------|----------|
| E03-T06-R01 | Every R-code in the catalog MUST map to a disposition (auto-reversal or manual-review); exhaustiveness enforced by test. | must |
| E03-T06-R02 | Irreversible methods MUST reject refund-to-original-method with a stable code. | must |
| E03-T06-R03 | Duplicate (payment, linked) pairs MUST be rejected. | must |
| E03-T06-R04 | Settlement batches MUST retain provider/batch trace IDs, gross/fee/net totals, asset, window, per-item status; duplicate provider delivery MUST return existing state without another posting. | must |
| E03-T06-R05 | Provider timeout MUST enter OUTCOME_UNKNOWN; retry MUST require status lookup first (no blind money-moving retry). | must |
| E03-T06-R06 | Workflow MUST follow REQUIRES_METHOD/ACTION → AUTHORIZED → CAPTURED → PENDING_SETTLEMENT → SETTLED / FAILED / RETURNED; these are never posting states. | must |
| E03-T06-R07 | New code MUST import only stdlib + `internal/domain/...`. | must |
