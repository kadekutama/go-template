## Objective

Define the smallest stable application contracts needed to post and read a ledger without waiting for payment, compliance, identity, or provider ports: inbound posting/read use cases, the atomic unit of work, durable idempotency, event boundary, clock, IDs, and command authorization.

## Scope

### In Scope

- `internal/application/port/{ledger,unit_of_work,idempotency,event,clock,ids,authz}.go`:
  - Inbound `PostLedgerPosting`, `GetPosting`, `GetBalance`, `ListEntries` with command/query/result contracts using ordinary Go `(R, error)` returns.
  - `UnitOfWork` + tx-scoped `Tx` bundling posting/entry/hold writes, balance checkpoint, idempotency result, and outbox facts in one atomic unit.
  - Durable `IdempotencyStore` (reserve/lease, replay on same fingerprint, conflict on different fingerprint).
  - `EventOutbox` (transactional append) vs `EventPublisher` (relay) boundary.
  - `Clock`, `IDGenerator` (alias of the domain contract), and command-level `Authorizer` with no adapter/provider types.
- `internal/application/port/port_test.go`: in-memory fakes proving implementability, an atomicity contract test (mid-transaction failure persists nothing), and an import-boundary test (no infrastructure imports).

### Out of Scope

- Handler implementations (E06-T01/T13), extended bounded-context ports (E06-T12), DTOs (E06-T02–T05/T13 adapt these core contracts).
- Adapter implementations (E07–E10 name the exact port they implement; E07 proves database serialization).
- Mockery wiring (`make generate-mocks` runs against these ports in E06-T12).

## Requirements

| ID | Requirement | Priority |
|----|-------------|----------|
| E06-T06-R01 | Inbound `PostLedgerPosting`, `GetPosting`, `GetBalance`, `ListEntries` MUST be defined with explicit command/query/result structs, `ctx` first, and ordinary `(R, error)` returns. | must |
| E06-T06-R02 | `UnitOfWork.Do` MUST document that posting, entries, holds, checkpoints, the idempotency result, and outbox facts commit atomically, and that the callback may run more than once on retryable failures. | must |
| E06-T06-R03 | `IdempotencyStore` MUST define reserve/lease, replay of the stored response on the same fingerprint, and conflict on a different fingerprint; strong-read and opaque-cursor expectations MUST be documented. | must |
| E06-T06-R04 | `EventOutbox` (transactional append) MUST be separated from `EventPublisher` (relay); `Clock`, `IDGenerator`, and `Authorizer` MUST NOT reference adapter, provider, or SDK types. | must |
| E06-T06-R05 | Port fakes MUST compile against these contracts without importing infrastructure packages, and a contract test MUST prove the `UnitOfWork` boundary cannot persist a partial posting. | must |

## Executable Scenarios

| ID | Given | When | Then |
|----|-------|------|------|
| E06-T06-S01 | Fake UoW + posting command | Do(write posting + outbox, return nil) | Both visible after commit |
| E06-T06-S02 | Fake UoW + posting command | Do(write posting, return error) | Nothing persisted (no partial posting) |
| E06-T06-S03 | Reserved fingerprint with stored response | Reserve(same fingerprint) | Original response replayed, executed once |

```go
// EventOutbox{Append(ctx, txFacts...) error}; EventPublisher{Publish(ctx, facts...) error}
// Clock{Now() time.Time}; IDGenerator (alias of domain valueobject.IDGenerator)
// Authorizer{Authorize(ctx, Subject{ID, TenantID}, Action, Resource) error}
```

## Invariants and Failure Semantics

- Transaction ownership: the `UnitOfWork` owns commit/rollback; callbacks never commit.
- Unknown commit outcome: `Do` surfaces transport/commit errors without claiming success; callers resolve via idempotent replay (E06-T01), never blind retry.
- Tenant/ledger scope rides every command and query; adapters MUST NOT return cross-tenant rows.
- Idempotency keys are caller-supplied; fingerprints are canonical hashes computed by the E06-T01 idempotency helper, stored opaquely here.
- Retry/timeout policy lives with callers/adapters; ports only document retry-safety of callbacks.
