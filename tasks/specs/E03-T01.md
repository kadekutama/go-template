# Task Specification: E03-T01 — Transfer domain service (immediate + scheduled + recurring + bulk rules)

**Task:** E03-T01
**Spec Status:** ready
**Author:** opencode-agent
**Reviewer:** repo-owner
**Last Updated:** 2026-09-14

## Objective

Ship pure transfer domain rules for immediate, scheduled, recurring, and bulk transfers with template support, enforcing ledger-core posting safety without I/O.

## Scope

### In Scope

- `internal/domain/service/transfer_service.go`: immediate transfer validation + posting-line construction (template-based debit source / credit destination liability).
- `internal/domain/service/scheduled_transfer.go`: schedule-time vs execution-time fund rules, recurrence expansion `root:{occurrence}`, optional schedule-time hold policy shape.
- `internal/domain/service/batch_transfer.go`: item independence, batch idempotency root, PARTIAL semantics.
- `internal/domain/service/transfer_template.go`: stored parameter-set templates (P2) that pre-fill transfers.

### Out of Scope

- Durable idempotency records, locking, persistence, outbox (E07).
- Application orchestration, API handlers (E06/E11).
- FX rate fetching (E10); conversion math itself is E03-T05.

## Requirements

| ID | Requirement | Priority |
|----|-------------|----------|
| E03-T01-R01 | Immediate transfers MUST validate both accounts exist, are ACTIVE, share tenant/ledger/asset, and source available covers amount; otherwise MUST fail with `ACCOUNT_FROZEN`/`ACCOUNT_CLOSED`/`TENANT_MISMATCH`/`CURRENCY_MISMATCH`/`INSUFFICIENT_FUNDS`. | must |
| E03-T01-R02 | Immediate transfers MUST construct template-based posting lines debiting source liability and crediting destination liability with positive minor units. | must |
| E03-T01-R03 | Scheduled transfers MUST validate everything except funds at schedule time; funds plus a durable reservation MUST be enforced atomically at execution (execution failure uses `INSUFFICIENT_FUNDS`, never schedule-time). | must |
| E03-T01-R04 | Recurrence expansion MUST use `root:{occurrence}` keys; occurrence derivation MUST be deterministic and MUST NOT reuse keys across roots. | must |
| E03-T01-R05 | Bulk batches MUST enforce item independence (sibling failure never rolls back siblings); batch result MUST be OK / PARTIAL / FAILED with per-item codes; batch idempotency root MUST scope item keys. | must |
| E03-T01-R06 | Templates MUST be stored parameter sets that pre-fill transfers; applying a template MUST NOT change validation rules. | must |
| E03-T01-R07 | Cross-currency transfers without an FX rate MUST fail `CURRENCY_MISMATCH`. | must |
| E03-T01-R08 | New code MUST import only stdlib + `internal/domain/...`. | must |
| E03-T01-R09 | Self-transfers (source == destination) MUST be rejected with `SELF_TRANSFER_REJECTED`; journal no-ops MUST NOT post. | must |

## Executable Scenarios

| ID | Given | When | Then |
|----|-------|------|------|
| E03-T01-S01 | Two ACTIVE same-tenant/ledger/asset accounts, sufficient funds | ValidateImmediate | pass + debit-source/credit-destination lines |
| E03-T01-S02 | Scheduled transfer, insufficient future funds | ValidateSchedule then ValidateExecution | schedule passes, execution fails `INSUFFICIENT_FUNDS` |
| E03-T01-S03 | Bulk batch with 1 failing item | EvaluateBatch | siblings complete, result PARTIAL with per-item codes |
| E03-T01-S04 | Cross-currency transfer without FX rate | ValidateImmediate | `CURRENCY_MISMATCH` |
| E03-T01-S05 | Recurring root `r1` with 3 occurrences | ExpandRecurrence | keys `r1:1`, `r1:2`, `r1:3` |
| E03-T01-S06 | Frozen source account | ValidateImmediate | `ACCOUNT_FROZEN` |
| E03-T01-S07 | Transfer with source == destination | ValidateImmediate / ValidateSchedule | `SELF_TRANSFER_REJECTED` |

## Invariants and Failure Semantics

- No mutable balances; funds come from caller-supplied available snapshot (strong-read projection owned by E07).
- Error codes stable: `ACCOUNT_FROZEN`, `ACCOUNT_CLOSED`, `TENANT_MISMATCH`, `LEDGER_MISMATCH`, `CURRENCY_MISMATCH`, `INSUFFICIENT_FUNDS`, `INVALID_TRANSFER_AMOUNT`, `BATCH_ITEM_REQUIRED`.
- No wall-clock reads inside validators except via explicit `time.Time` params; no retries; tenant from context-equivalent params, never body-only trust (checked again at app/persistence boundary).
- Workflow states are not posting states (ledger-core §1).
