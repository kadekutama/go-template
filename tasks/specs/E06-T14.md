# Task Specification: E06-T14 — UUID identity application port (flows + aliases)

**Task:** E06-T14  
**Spec Status:** ready  
**Author:** muse-spark  
**Reviewer:** repository-owner  
**Last Updated:** 2026-09-17

## Objective

Port application flows to DB-generated UUID identity per ADR-019: stop
pre-minting entity IDs, read back database-assigned IDs, populate tenant and
ledger aliases, and keep idempotent replay plus provider keying intact.

## Scope

### In Scope

- Remove entity pre-mint `NewID` calls where the database now generates the
  ID (payout, topup, transfer, posting, entries, account, dispute, report,
  compliance, export flows); read back `RETURNING` IDs from repositories.
- Verify per flow that no external call consumes an entity ID before its row
  exists; where it does, switch the external key to the idempotency key
  first (ordered checklist in implementation, one flow at a time:
  capture/settlement, refund incl. unknown outcomes, payout
  submit/settle/fail/return, internal/scheduled transfer).
- Alias assignment: slugify tenant/ledger names, retry with numeric suffix
  on uniqueness conflict.
- `IDGenerator` port stays for event IDs, keys, and non-persisted
  correlation; only entity persistence moves.

### Out of Scope

- Schema, models, repositories, RLS, triggers (owned by E07.1-T06).
- Domain value objects (already UUID-shaped; untouched).
- Provider sandbox behavior changes (E10); endpoint/API changes (E11+).

## Requirements

| ID | Requirement | Priority |
|----|-------------|----------|
| E06-T14-R01 | Handlers MUST NOT pre-mint IDs for DB-generated entities; returned DTOs MUST carry the database-assigned canonical UUID. (Mechanical conversion lands in E07.1-T06 with the port widening; this task proves and extends it.) | must |
| E06-T14-R02 | Every external (provider) call MUST key on the idempotency key, never on a not-yet-persisted entity ID; the per-flow audit MUST be recorded in evidence. | must |
| E06-T14-R03 | Replay of an identical idempotent request MUST return the original response with the original IDs; changed fingerprints MUST conflict. | must |
| E06-T14-R04 | Tenant/ledger creation MUST assign aliases (slug + suffix retry); alias collisions MUST surface as conflicts, never silent renames. | must |
| E06-T14-R05 | Application suite MUST stay ≥85% statement coverage with `-race -count=3` (G3 bar preserved). | must |

## Executable Scenarios

| ID | Given | When | Then |
|----|-------|------|------|
| E06-T14-S01 | Authorized payout request with fresh key | Handler executes twice with same key | One payout row; both responses identical incl. IDs. |
| E06-T14-S02 | Same key, changed amount | Handler executes | Fingerprint conflict error; no new row. |
| E06-T14-S03 | New tenant named same as existing | Onboarding executes | Second alias gets numeric suffix; both tenants retrievable. |
| E06-T14-S04 | Provider sandbox call | Any money flow executes | Outbound key is the idempotency key in every flow. |

## Interfaces and Data

- DTO IDs remain UUID strings (wire format unchanged); only their origin
  moves from app-minted to database-assigned.
- Alias fields surface on tenant/ledger DTOs.
- No new ports; `IDGenerator` remains for events/keys.

## Invariants and Failure Semantics

- Saga crash-resume, unknown-outcome (never blind-retry), and maker-checker
  semantics unchanged; only ID provenance moves.
- Alias slugify is deterministic; suffix retry is bounded (fail after N
  collisions with a typed conflict, never unbounded loop).
