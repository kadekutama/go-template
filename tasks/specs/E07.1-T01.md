## Objective

Transition the database migration framework from the legacy bespoke stdlib runner (`schema_migrations`, rigid `BeginTx`, gapless 1..N check) and `golang-migrate` CLI to Pressly Goose v3 (`github.com/pressly/goose/v3` v3.28.0) for in-process execution and Ariga Atlas CLI (v1.3.0) for pre-deployment CI/CD safety linting and Merkle-tree checksum validation. Consolidate baseline migrations `000001`–`000004` into unified single-file Goose format without renumbering, implement a one-time ledger bootstrap from `schema_migrations` to `goose_db_version`, support 14-digit UTC timestamps (`YYYYMMDDHHMMSS_<name>.sql`) for new migrations, and extend the schema with Citus 14.0 tenant-sharded distribution using `-- +goose NO TRANSACTION`.

## Scope

### In Scope

- **Runtime Migration Engine (`internal/infrastructure/database/migration/migrate.go`)**:
  - Implement `Runner` encapsulating `goose.NewProvider` with `goose.DialectPostgres`, `goose.WithAllowOutofOrder(true)`, and embedded FS support.
  - Implement automatic idempotent one-time bootstrap copying applied versions from legacy `schema_migrations` into `goose_db_version` if the legacy table exists.
  - Implement `List(fsys, dir)` returning chronological `[]Migration` with `int64` versions and names.
  - Expose `Up(ctx)`, `Down(ctx)`, and `Version(ctx) (int64, error)`.
- **Migration File Consolidation (`internal/infrastructure/database/migration/versions/`)**:
  - Consolidate legacy `000001`–`000004` split `.up.sql`/`.down.sql` migrations into unified single-file Goose migrations **retaining their original numeric prefixes**:
    - `000001_ledger_core.sql` (enclosing PL/pgSQL functions and triggers in `-- +goose StatementBegin` / `-- +goose StatementEnd`)
    - `000002_idempotency_outbox.sql`
    - `000003_workflow_tenancy_recon.sql`
    - `000004_rls_policies.sql` (enclosing anonymous `DO $$ ... $$;` loops in `-- +goose StatementBegin` / `-- +goose StatementEnd`)
  - New migrations created after `000004` use 14-digit UTC timestamps.
- **Atlas Checksum Integrity**:
  - Generate and commit the cryptographic migration manifest `internal/infrastructure/database/migration/versions/atlas.sum` using `atlas migrate hash`.
- **Citus Tenant Sharding Migration**:
  - Add `internal/infrastructure/database/migration/versions/20260901000005_citus_distribution.sql` using `-- +goose NO TRANSACTION` for `SELECT create_distributed_table(...)` and `SELECT create_reference_table(...)`.
- **Gate Check Tooling (`tasks/scripts/check-tasks.py`)**:
  - Update `--migrations` logic to glob `*.sql` (ignoring `atlas.sum`), verify legacy 1..4 gapless sequence, verify subsequent versions match 14-digit timestamp pattern, and ensure `atlas.sum` presence.
- **Toolchain & Developer Scripts**:
  - Update `scripts/dev/setup.sh` to install `atlasgo` via Pixi and `goose` via `go install`.
  - Update `scripts/db/migrate.sh` to drive `goose` CLI commands (`up`, `down`, `status`, `version`, `reset`, `create`) and `atlas` CLI commands (`lint`, auto-hashing `atlas.sum`).
  - Update `Makefile` with `make migrate-status` and `make migrate-lint`.
- **Test Suite Updates**:
  - Update unit tests in `internal/infrastructure/database/migration/migration_test.go` with table-driven tests asserting versioning, SQL type constraints (`BIGINT`, `NUMERIC(38,0)`, no floats), and reversibility.
  - Update integration tests in `test/integration/persistence/persistence_test.go`.
- **Dependencies**:
  - Update `go.mod`, `go.sum`, and `internal/shared/deps/deps.go` to replace `github.com/golang-migrate/migrate/v4` with `github.com/pressly/goose/v3` (v3.28.0).

## Invariants and Failure Semantics

- **Strict Reversibility**: Every migration file must contain valid, non-empty Up and Down blocks.
- **History Immutability**: Historical migrations `000001`–`000004` maintain their numeric versioning; changes alter `atlas.sum` and fail CI.
- **Seamless Idempotent Bootstrap**: Existing databases with legacy `schema_migrations` must not re-run migrations 1..4 upon upgrading to Goose, and multi-pod runner restarts must not insert duplicate rows into `goose_db_version`.
- **Citus Non-Transactional Execution**: Citus sharding operations must execute outside ambient transactions.
- **Pure-Compute Go Migrations**: In-process `.go` migrations never perform external network I/O; service-coupled backfills run in E14 jobs.
