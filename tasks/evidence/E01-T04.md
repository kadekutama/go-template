## slog-integration assessment (owner asked; zerolog README verified 2026-09-14)
- `zerolog.NewSlogHandler` EXISTS in v1.35.1: it routes **slog API → zerolog
  engine** (`slog.New(handler)`). Direction matters: it does NOT make our
  custom port slog-compatible, and our Panic/Fatal/Trace semantics do not map
  onto slog levels — so adopting it inside OUR adapter would add a hop
  (port → slog.Record → handler → core) with zero behavioral gain. NOT adopted.
- Genuinely beneficial for **E11 Echo middleware** (Echo v5's native API is
  slog): E11 can build framework-facing `*slog.Logger`s on the zerolog engine
  with one line (`slog.New(zerolog.NewSlogHandler(zl))`), keeping uniform JSON
  output for framework logs. Recorded as the E11 integration note; no code
  added now (E11 scope; avoids premature API + wrong-direction imports).
