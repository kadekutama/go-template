## Objective

Ship pure break-resolution rules: investigation actions, SoD-gated approvals, and the OPEN→IN_REVIEW→RESOLVED/ACKNOWLEDGED/ESCALATED state machine with acknowledgement expiry.

## Scope

### In Scope

- `internal/domain/service/break_resolution.go`: `TransitionBreak`, `ValidateResolution`, `IsAcknowledgementExpired`, adjustment-line builder.
- `internal/domain/valueobject/approval.go`: `ApprovalDecision`, `ResolutionAction`, `BreakStatus` + parsers and SoD rule.

### Out of Scope

- Persistence, dashboard, notifications (E07/E11); posting commit path (E07); cron (E14).

## Normative Inputs

- `tasks/epics/E04-compliance.md#E04-T02` for the backlog boundary.
- `docs/ledger-core.md §3.8` (reversal/adjustment is a new balanced linked posting with reason + actor; history immutable).
- `docs/money-flow.md §6.2` (adjust/external-error/escalate; resolution entry linked to break).
- `docs/fintech-ledger-features.md §4.1–§4.2` (SOX segregation of duties, control owners, evidence).

## Requirements

| ID | Requirement | Priority |
|----|-------------|----------|
| E04-T02-R01 | Resolution actions MUST be exactly `ADJUST_LEDGER`, `MARK_EXTERNAL_ERROR`, `ESCALATE_TO_COMPLIANCE`, `ACKNOWLEDGE`, each with reason code, evidence reference, owner, actor, and audit link (`EVIDENCE_REQUIRED` otherwise). | must |
| E04-T02-R02 | `ADJUST_LEDGER` MUST construct a balanced linked adjustment (debit+credit, positive minors, same asset, refs break ID + original posting) and MUST link the adjustment entry ID in the resolution. | must |
| E04-T02-R03 | SoD rule: for adjustments above the configured threshold, maker/resolver MUST differ from approver (`SELF_APPROVAL_FORBIDDEN` otherwise); at/below threshold self-approval is allowed. | must |
| E04-T02-R04 | State machine MUST be OPEN → IN_REVIEW → RESOLVED / ACKNOWLEDGED / ESCALATED; ACKNOWLEDGED with past expiry MUST re-OPEN via `ReopenIfExpired` (`ACK_ACTIVE` if not expired, `ILLEGAL_TRANSITION` if not acknowledged); illegal jumps MUST fail (`ILLEGAL_TRANSITION`). | must |
| E04-T02-R05 | Every resolution MUST be reproducible from explicit time params (no hidden clock). Whitespace-only identity MUST be rejected. | must |
| E04-T02-R06 | New code MUST import only stdlib + `internal/domain/...`. | must |

## Executable Scenarios

| ID | Given | When | Then |
|----|-------|------|------|
| E04-T02-S01 | OPEN break, ACKNOWLEDGE with reason+evidence+owner+actor | ValidateResolution + TransitionBreak | IN_REVIEW then ACKNOWLEDGED with expiry recorded |
| E04-T02-S02 | Above-threshold adjust where maker == approver | ValidateResolution | `SELF_APPROVAL_FORBIDDEN` |
| E04-T02-S03 | Expired acknowledgement (expires < now) | IsAcknowledgementExpired | true → re-OPEN transition allowed |
| E04-T02-S04 | ADJUST_LEDGER resolution | BuildAdjustmentLines | balanced debit==credit lines linked to break + original |
| E04-T02-S05 | OPEN → RESOLVED direct jump | TransitionBreak | `ILLEGAL_TRANSITION` |

// BuildAdjustmentLines(breakID, originalPostingID, debitAccount, creditAccount string, amountMinor int64, assetCode string) ([2]AdjustmentLine, error)

## Invariants and Failure Semantics

- Adjustments never mutate history; they are new linked facts. Stable codes: `EVIDENCE_REQUIRED`, `SELF_APPROVAL_FORBIDDEN`, `ILLEGAL_TRANSITION`, `ADJUSTMENT_UNBALANCED`.
- Acknowledgement expiry uses explicit `Now`; expired ACK re-opens rather than silently staying closed.
