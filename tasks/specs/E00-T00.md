## Objective

Create a shared, reproducible Git coordination boundary so task claims, diffs,
evidence, and takeovers can reference exact commits without including unrelated work.

## Scope

### In Scope

- Repository boundary decision, initial tracked baseline, shared remote/default
  branch, ownership/merge policy, and fresh-checkout proof.

### Out of Scope

- Go bootstrap, source implementation, release branching, CI jobs beyond the
  task-metadata smoke check, and destructive rewriting of existing sibling history.

## Normative Inputs

- `tasks/SDD.md §3, §4, §6` for claims, takeover, and parallel-work rules.
- Current evidence (2026-09-13): `git rev-parse --show-toplevel` and
  `git rev-parse --absolute-git-dir` resolve to `go-template/`; the checkout has
  no `HEAD`, no `origin`, and its `.git` mount is read-only, so the baseline
  commit cannot yet be written. An authorized `git branch -m main` attempt was
  rejected while creating `.git/HEAD.lock`; the symbolic branch therefore
  remains `master` until the metadata mount is writable.
- The repository owner's hosting, visibility, and monorepo decision.

## Interfaces and Data

The coordination interface is Git commit identity plus the Markdown task claim.
The owner-approved default branch is `main`; the remote provider/URL is
intentionally unspecified until hosting is configured. Every participating
harness must be able to fetch that branch or use the same serialized local
worktree coordinator.

## Invariants and Failure Semantics

- No agent may initialize a nested repository, rewrite history, or publish a
  remote until the owner resolves the boundary and hosting choice.
- A missing HEAD/origin blocks task claims rather than falling back to timestamps.
- Existing sibling data and unrelated uncommitted changes are preserved.
- Credentials and remote tokens never appear in governance or evidence files.

## Change Surface

**Owns:** owner-approved Git metadata/configuration, `.github/CODEOWNERS`, and
`docs/development/repository-governance.md`.  
**Coordinates:** parent repository owners and any existing CI/branch policy.  
**Must Not Touch:** unrelated siblings, implementation files, history rewriting,
or remote publication without explicit owner authorization.
