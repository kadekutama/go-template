## Requirements

| ID | Requirement | Priority |
|----|-------------|----------|
| E07-T01-R01 | Core tables (ledgers, accounts, postings, entries, holds, checkpoints) MUST carry tenant+ledger scope, BIGINT minor-unit entry amounts with positive-entry checks, NUMERIC(38,0) checkpoint aggregates, asset registry, and monotonic cursor/sequence columns. | must |
| E07-T01-R02 | Migrations MUST be one version per group, reversible up/down, embedded via `embed.FS`, numbered with zero gaps (000001 core, 000002 idempotency+outbox). | must |
| E07-T01-R03 | The posting path MUST be one explicit transaction: reserve durable idempotency hash, lock accounts deterministically, enforce same tenant/ledger + per-asset balance, insert posting/entries/checkpoint/outbox, store the response, commit once. | must |
| E07-T01-R04 | Database roles/constraints MUST reject unbalanced inserts and UPDATE/DELETE of posted facts; reversals MUST be new linked postings. | must |
| E07-T01-R05 | The implementation MUST NOT add a mutable balance column or cache-as-truth projection; balances derive from entries (+ checkpoints as rebuildable reference) until ADR-011 is accepted. | must |
| E07-T01-R06 | Adapters MUST implement `repository.{Ledger,Posting,...}` + `port.{UnitOfWork,IdempotencyStore,EventOutbox}` without importing application/interface packages (dependency points inward). | must |

| E07-T01-S05 | Same idempotency key + same fingerprint | Second commit | Original response replayed, single posting (no duplicate) |

| E07-T01-S07 | Concurrent spends exceeding available (overdraft disabled) | Parallel commits | Serialized; never negative (deterministic lock order, no deadlock) |

## Invariants and Failure Semantics

- Atomicity: posting/entries/checkpoint/idempotency-response/outbox commit once or not at all.
- Unknown commit outcome surfaced as error; callers resolve via idempotent replay, never blind retry.
- Deterministic account lock order (sorted IDs) prevents deadlocks under contention.
- Tenant/ledger scope on every row; cross-scope writes rejected.
- Callbacks may run more than once (retryable failures); stores are tx-scoped, no provider calls inside.

## Amendment (audit 2026-09-16)

- `Commit` now locks involved accounts (`SELECT ... FOR UPDATE`, sorted acquisition), verifies same tenant/ledger scope + ACTIVE status, assigns per-account `account_seq` (`MAX+offset`), and captures `ledger_seq` cursors (`CursorOf`; tx-scoped `txPostings` records it for `Tx.Cursor`).
- Idempotency `Complete` scopes to the Reserved tenant; cursor pagination uses numeric `account_seq`/`ledger_seq` cursors (entry-ID cursors rejected); posting pages assemble in batch (no N+1).
- Per-account available-balance enforcement against holds stays with the command layer (policy-owned overdraft decisions); the DB trigger enforces per-posting per-asset balance. No signature changes to domain/application ports.
- `LedgerToEntity` surfaces invalid stored rows instead of silent zero values.
