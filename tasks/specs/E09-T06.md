# Task Specification: E09-T06 — OpenBao Transit envelope encryption + PII field handling

**Task:** E09-T06
**Spec Status:** ready
**Author:** muse-spark
**Reviewer:** kadekutama
**Last Updated:** 2026-09-23

## Objective

Deliver PII field encryption behind `port.EnvelopeCrypto` with AES-256-GCM envelope (DEK/KEK), per-record random nonces, AAD binding (tenant + purpose), key rotation via re-wrap, and crypto-shredding for E04-T04 erasure.

## Scope

### In Scope

- `internal/infrastructure/crypto/` package: `envelope.go` (Encrypt/Decrypt), `transit.go` (KEK seam: local HSM-fake default, OpenBao Transit HTTP compatible), `pii.go` (struct-tag `pii:"email"` encrypt-on-write/decrypt-on-authorized-read helpers + PAN tokenize seam).
- `Module() fx.Option` exposing `port.EnvelopeCrypto`.
- Unit tests (nonce uniqueness, AAD tamper, rotation re-wrap, shred, cancel). No OpenBao server required.

### Out of Scope

- OpenBao cluster ops (E17), ledger balance math (untouched by shred; sums hold), full PAN vault product (tokenize seam only).

## Normative Inputs

- `tasks/epics/E09-identity-security.md#E09-T06` for the backlog boundary.
- `SPEC.md §14` (AES-256-GCM, rotation, crypto-shredding) and `docs/architecture/ADR-016-secrets-management-openbao.md`.
- `internal/application/port/crypto.go` (`EncryptedEnvelope`, `EnvelopeCrypto` contract).
- `tasks/epics/E04-compliance.md#E04-T04` (erasure via shred).

## Requirements

| ID | Requirement | Priority |
|----|-------------|----------|
| E09-T06-R01 | `Encrypt` MUST use a fresh random 256-bit DEK per envelope (or per-key version) with a random nonce; identical plaintext MUST yield different ciphertext. | must |
| E09-T06-R02 | AAD MUST bind tenant + purpose + key ID; tampered AAD/nonce/ciphertext MUST fail decryption closed. | must |
| E09-T06-R03 | Key rotation MUST re-wrap DEKs without caller changes; decrypt MUST resolve the envelope `KeyID` version. | must |
| E09-T06-R04 | Crypto-shred (destroy key version) MUST make its envelopes unrecoverable while ledger sums hold. | must |
| E09-T06-R05 | Plaintext PII MUST never reach logs/errors/outbox; `pii` struct tags MUST drive field selection. | must |
| E09-T06-R06 | The adapter MUST implement `port.EnvelopeCrypto` exactly and MUST expose `Module() fx.Option`. | must |

## Executable Scenarios

| ID | Given | When | Then |
|----|-------|------|------|
| E09-T06-S01 | Same plaintext twice | `Encrypt` twice | Different nonce + ciphertext; both decrypt |
| E09-T06-S02 | Tampered AAD/nonce | `Decrypt` | Authentication failure, no plaintext |
| E09-T06-S03 | Rotated KEK | `Decrypt` old envelope | Passes via versioned `KeyID`; new encrypts use new version |
| E09-T06-S04 | Shredded key version | `Decrypt` | Fails closed; unrelated versions still open |
| E09-T06-S05 | Canceled context | `Encrypt`/`Decrypt` | Context error |

## Interfaces and Data

```go
// crypto.Params{KEK KeyEncryptionKey, Clock}

// crypto.NewEnveloper(CryptoParams) (*Enveloper, error); Encrypt(ctx, tenant, purpose, plaintext) (port.EncryptedEnvelope, error)

// Sentinel errors: ErrAuthFailed, ErrUnknownKey, ErrShredded
// Module() fx.Option
```

## Invariants and Failure Semantics

- Master keys never leave the KEK seam; DEKs are random per envelope lineage.
- Decrypt fails closed on tamper/unknown/shredded keys; no plaintext on error paths.
