## Objective

Implement the continuous profiling infrastructure adapter (`internal/infrastructure/profiling/`) using `github.com/grafana/pyroscope-go v1.4.3` and `github.com/grafana/otel-profiling-go v0.7.0`, correlate OpenTelemetry spans (`internal/infrastructure/tracing/otel.go`) with CPU/heap/goroutine/mutex/block profiles, expose validated runtime configuration (`observability.profiling` / `profiling`), and wire lifecycle management into `internal/shared/di/infrastructure.go`.

## Scope

### In Scope

- `go.mod` / `go.sum`: pin `github.com/grafana/pyroscope-go v1.4.3` and `github.com/grafana/otel-profiling-go v0.7.0`.
- `internal/shared/deps/deps.go` & `internal/shared/deps/deps_test.go`: add blank import anchors and version smoke tests.
- Runtime configuration (`internal/infrastructure/config/config.go`, `config/config.yaml`, `config/schemas/config.json`, `internal/infrastructure/config/config_test.go`):
  - Add `ProfilingConfig` (default `enabled: false`, `server_address: "http://localhost:4040"`, `application_name: "fintech-ledger"`, `upload_rate: 15s`, `mutex_profile_fraction: 5`, `block_profile_rate: 5`, `disable_gc_runs: false`, `tags: map[string]string`).
- Create `internal/infrastructure/profiling/`:
  - `config.go` & `params.go`: `Config` validation via `internal/shared/kernel/validate` + PII/high-cardinality tag key rejection (`tenant_id`, `account_id`, `user_id`, `email`, `pan`); `ProfilerParams` Parameter Object (`Config`, `Logger`).
  - `profiler.go`: `Profiler` struct with unexported fields, `NewProfiler(ProfilerParams) (*Profiler, error)`, `Start(ctx context.Context) error`, `Stop(ctx context.Context) error`, and `WrapTracerProvider(tp trace.TracerProvider) trace.TracerProvider` (using `otelpyroscope.NewTracerProvider`).
  - `module.go`: `fx.Module("profiling", ...)` registering `NewProfiler` and `fx.Lifecycle` `OnStart`/`OnStop` hooks.
  - `profiler_test.go` & `module_test.go`: table-driven unit tests using `httptest.NewServer`, `fx.ValidateApp`, and `fxtest.New`.
- Integrate `otelpyroscope.NewTracerProvider` in `internal/infrastructure/tracing/otel.go` when profiling is enabled. This requires the additive `tracing.Config.ProfilingEnabled` field and its one-line mapping in `internal/infrastructure/config/mapping.go`.
- Wire `profiling.Module()` into `internal/shared/di/infrastructure.go`.

### Out of Scope

- `docker-compose.observability.yml` Pyroscope server container, Grafana `tracesToProfiles` provisioning, and loopback-only `net/http/pprof` HTTP listener (`E15-T07`).
- Offline `google/pprof` CLI benchmark flamegraphs and `default.pgo` generation (`E19-T05`).

## Invariants and Failure Semantics

- **Zero Domain/Application Coupling**: `pyroscope-go` and `otel-profiling-go` are imported only in `internal/infrastructure/profiling`, `internal/infrastructure/tracing`, and `internal/shared/deps`.
- **Cardinality & Privacy Protection**: High-cardinality or sensitive keys (`tenant_id`, `account_id`, `user_id`, `email`, `pan`) are forbidden in profiler tags.
- **Deterministic Shutdown**: Sequential `Stop` calls are idempotent and reset global `runtime` mutex/block rates to `0`; fx serializes lifecycle hooks.

## Test Exceptions

The AGENTS.md unit-test policy normally limits assertions to the complete
return tuple of the function under test. These essential side effects cannot be
observed from those return values and are explicitly permitted here:

- **S01 disabled lifecycle:** `requests.Load()` observes that the disabled path
  opens no network connection. `Start`/`Stop` return only `error`; the no-HTTP
  scenario is otherwise unobservable.
- **S02 enabled lifecycle:** the `/ingest` request counter observes flush, and
  `runtime.SetMutexProfileFraction(-1)` observes the process-global sampling
  rate. `Start`/`Stop` return only `error`; Go exposes no block-rate getter, so
  the mutex rate is the observable counterpart of the shared reset path.
- **R06 span correlation:** the span attribute `pyroscope.profile.id` is
  observed after ending a span created from the wrapped provider. The wrapper
  returns only the `TracerProvider`; correlation is a provider behavior.
- **S04 fx graph/lifecycle:** `fx.ValidateApp` and `fxtest.New` observe graph
  resolution and startup/shutdown ordering. `Module()` returns only an
  `fx.Option`, and lifecycle hooks report through fx. `fx.ValidateApp` graph
  errors have no exported sentinel values, so the negative cases assert error
  presence rather than a concrete error value.
- **R02 base config:** `TestBaseConfigProfilingDefaults` compares the
  `Config.Observability.Profiling` projection because the full `Config` value
  contains unrelated sections outside this task's change surface; the
  projection is compared as one aggregate value and the `error` is asserted
  once.
