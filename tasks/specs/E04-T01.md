# Task Specification: E04-T01 — Reconciliation matching rules + break taxonomy

**Task:** E04-T01
**Spec Status:** ready
**Author:** opencode-agent
**Reviewer:** repo-owner
**Last Updated:** 2026-09-14

## Objective

Ship pure reconciliation matching rules: deterministic 3-way match of ledger facts vs external statement lines with versioned rules, rail/currency tolerance policy, and the five-type break taxonomy.

## Scope

### In Scope

- `internal/domain/service/reconciliation_service.go`: `MatchStatements`, `AutoResolveBreak`, deterministic grouping, tolerance lookup, duplicate detection.
- `internal/domain/valueobject/break_type.go`: `BreakType` constants + `ParseBreakType`.
- `internal/domain/valueobject/match_result.go`: `MatchDecision` (`MATCHED`, `BREAK`) + confidence/actor record.
- `internal/domain/entity/reconciliation_run.go`: `ReconciliationRun` + `ExternalStatementLine` snapshot shape.
- `internal/domain/entity/reconciliation_break.go`: `ReconciliationBreak` with per-type evidence fields.

### Out of Scope

- Parsers (MT940/BAI2/CSV) and bank fetching (E10); persistence/RLS (E07); handlers/API (E06/E11); cron scheduling (E14).

## Normative Inputs

- `tasks/epics/E04-compliance.md#E04-T01` for the backlog boundary.
- `docs/ledger-core.md §1, §3.8` (settlement compares external facts with postings; never mutates history; corrections are new postings).
- `docs/money-flow.md §6.1–§6.2` (daily flow, four break types + duplicate, auto-resolve timing <24h only).
- `docs/domain-events.md §3.7` (`reconciliation.run.started/completed`, `break.found/resolved/acknowledged`).
- `docs/fintech-ledger-features.md §4.2` (daily/inter-system reconciliation, break detection).

## Requirements

| ID | Requirement | Priority |
|----|-------------|----------|
| E04-T01-R01 | Match MUST support 1:1 exact matches on (reference, asset, amount) within the configured timing window and record rule version, confidence, inputs, and decision actor per group. | must |
| E04-T01-R02 | Match MUST support 1:N/N:1 splits where the leg sum equals the counterparty amount within tolerance, with the same provenance record as R01. | must |
| E04-T01-R03 | Amount tolerance MUST come from an explicit rail/currency policy (`ToleranceMinor` per rail+asset); a global epsilon MUST NOT be used (`TOLERANCE_POLICY_REQUIRED` otherwise). | must |
| E04-T01-R04 | Break taxonomy MUST be exactly `MISSING_IN_LEDGER`, `MISSING_IN_BANK`, `AMOUNT_MISMATCH`, `DATE_MISMATCH`, `DUPLICATE`, each carrying its required evidence fields (refs, expected/actual, window, rule version). | must |
| E04-T01-R05 | Same ledger+external input MUST yield identical matched groups and breaks on repeat runs (deterministic ordering and IDs). | must |
| E04-T01-R06 | Auto-resolve MUST only close `DATE_MISMATCH`/`MISSING_*` timing skew inside the versioned timing/rail policy; it MUST NEVER close `AMOUNT_MISMATCH` (`AUTO_RESOLVE_FORBIDDEN` otherwise). | must |
| E04-T01-R07 | External lines MUST carry immutable snapshot identity (source account, coverage interval, hash, parser version, raw lineage); lines without identity MUST be rejected (`SNAPSHOT_IDENTITY_REQUIRED`). Ledger facts MUST carry posting id, reference, positive amount, asset, and effective time (`POSTING_ID_REQUIRED`/`LEDGER_REFERENCE_REQUIRED`/`INVALID_ENTRY_AMOUNT` otherwise); whitespace-only identity MUST be rejected. | must |
| E04-T01-R08 | New code MUST import only stdlib + `internal/domain/...`. | must |
| E04-T01-R09 | Sums MUST use checked int64 arithmetic; overflow MUST fail with `AMOUNT_OVERFLOW`, never wrap. Duplicate rail+asset tolerance entries with conflicting values MUST fail with `TOLERANCE_POLICY_CONFLICT`. | must |
| E04-T01-R10 | Match groups MUST record decision (`MATCHED`), rule version, confidence, ledger/external sums, inputs (refs), and decision actor; break/group IDs MUST embed the run ID for cross-run uniqueness. Auto-resolve MUST require a decision actor (`DECISION_ACTOR_REQUIRED`). | must |

## Executable Scenarios

| ID | Given | When | Then |
|----|-------|------|------|
| E04-T01-S01 | Golden ledger 3 facts + statement 3 lines (1 exact, 1 split 1:2, 1 missing) | MatchStatements | 2 matched groups + 1 MISSING_IN_BANK break with rule version recorded |
| E04-T01-S02 | Same input twice | MatchStatements twice | byte-identical groups and breaks (determinism) |
| E04-T01-S03 | Amount differs beyond tolerance, same ref/date | MatchStatements | AMOUNT_MISMATCH break, never auto-matched |
| E04-T01-S04 | Auto-resolve called on AMOUNT_MISMATCH | AutoResolveBreak | `AUTO_RESOLVE_FORBIDDEN` error |
| E04-T01-S05 | Duplicate external reference with same hash | MatchStatements | DUPLICATE break with both line IDs in evidence |
| E04-T01-S06 | Missing tolerance for rail+asset | MatchStatements | `TOLERANCE_POLICY_REQUIRED` |
| E04-T01-S07 | Overflow sums (MaxInt64 legs) | MatchStatements | `AMOUNT_OVERFLOW` |
| E04-T01-S08 | Empty/whitespace ledger reference | MatchStatements | `LEDGER_REFERENCE_REQUIRED`/`POSTING_ID_REQUIRED` |
| E04-T01-S09 | Orphan external line, empty ledger | MatchStatements | `MISSING_IN_LEDGER` with refs + amounts |

## Invariants and Failure Semantics

- No mutation of postings; matching is a pure read-model comparison. Time via explicit params. Stable codes: `TOLERANCE_POLICY_REQUIRED`, `TOLERANCE_POLICY_CONFLICT`, `SNAPSHOT_IDENTITY_REQUIRED`, `LEDGER_REFERENCE_REQUIRED`, `POSTING_ID_REQUIRED`, `AUTO_RESOLVE_FORBIDDEN`, `AMOUNT_OVERFLOW`, `DECISION_ACTOR_REQUIRED`, `DUPLICATE_REFERENCE`.
- Every match group records rule version + actor; every break records rule version + evidence.
