## Objective

Move the authorization pin from `github.com/casbin/casbin/v2 v2.8.0` to the current casbin v3 release while preserving authorization outcomes and stored policy data. Upstream documents v3 as a module-path major with identical APIs.

## Scope

### In Scope

- `go.mod` / `go.sum`: `github.com/casbin/casbin/v2 v2.8.0` → `github.com/casbin/casbin/v3 v3.11.0` (latest checked 2026-10-04; Go module proxy reports v3.11.0 published 2026-06-23), `go mod tidy`. Recheck at implementation; if latest changes, amend and reapprove the packet before implementation.
- `internal/infrastructure/auth/rbac/enforcer.go`: import `github.com/casbin/casbin/v2` + `v2/model` → `v3` + `v3/model`. No logic change.
- `internal/shared/deps/deps.go`: casbin blank-import anchor `/v2` → `/v3`.
- `SPEC.md §2` casbin row v2.8.0 → v3 pin.
- `docs/architecture/ADR-025-casbin-v3.md`: path-only major record, no-API-change evidence, rollback (re-pin v2).
- `docs/architecture/README.md`: ADR-025 index row.
- `internal/infrastructure/auth/rbac/{version_parity_test.go,testdata/casbin-v2.8.0-parity.json}`: executable v2-baseline versus v3 decision parity test. Before changing imports, add temporary uncommitted `casbin_v2_baseline_test.go` (`package rbac_test`, test `TestWriteCasbinV2Baseline`) under the existing v2.8.0 module; serialize the production model's fixed request/policy matrix, preserve the fixture and v2 checksum, then remove the helper before adding the permanent v3 test. Final source must contain no `/v2` import.
- `tasks/tracking/GATES.md`: add T06 authorization-parity proof to the planned E09.1 G4 slice.
- `tasks/epics/E10-integrations.md`: add E09.1-T06 to each provider task's prerequisite list so the E09.1 hard gate and shared module-file ordering are enforced at task level.

### Out of Scope

- Model/policy semantics: `model.conf`, `casbin_rules` rows/migration, loader logic, and threshold ABAC stay untouched (E09-T03 owns).
- Completed history: E09-T03 and E01-T01 packets/evidence stay as written; this packet supersedes their v2 pin references without rewriting them.
- gocron/gocron-ui/x-sync pins (E09.1-T01/T02/T04 own); any new casbin feature adoption (logger, `GetAllUsers`, cycle detection, `Explain`).

## Invariants and Failure Semantics

- Authorization behavior is frozen: any allow/deny delta vs v2 is a migration bug, not an accepted change. The parity corpus is table-driven and its permanent test compares against a pre-upgrade v2.8.0 fixture; the temporary generator is removed before completion. Existing loader tests prove the unchanged tuple mapping; no ordering is inferred from the loader's unordered DB query.
- Rollback is re-pin v2 + revert import paths; recorded in the ADR. Policy data needs no rollback (untouched).
- Sequenced after E09.1-T05, which transitively completes T01–T04 and owns ADR-022…024 index work. This serializes T06 behind all known E09.1 `go.mod`/`go.sum` owners and avoids overlapping the architecture-index update.
- E10 provider tasks explicitly depend on T06 as part of the E09.1 hard prerequisite. This is also required to serialize shared `go.mod`/`go.sum` edits; separate worktrees alone do not authorize overlapping changes.
