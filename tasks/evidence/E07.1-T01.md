## Deviations and Residual Risk

- Audit 2026-09-17 (post-implementation) measured the real per-table
  deferral taxonomy on Citus 14.0 by executing the migration's Up block via
  psql with server messages visible (goose/pgx do not forward NOTICEs):
  - `accounts`, `holds`: `referenced table "assets" must be a distributed table or a reference table`
  - `postings`, `entries`: `cannot distribute relation ... because it has triggers` (immutability/balance guards — must never be dropped casually)
  - `outbox_events`: `cannot create constraint on "outbox_events"` (`UNIQUE (aggregate_id, aggregate_version)` lacks the distribution column)
  - `idempotency_records`: distributed (`PRIMARY KEY (tenant_id, key)` already covers it)
  - `assets` reference: deferred by cascade contention (`cannot modify table "ledgers" because there was a parallel operation on a distributed table`)
  - A `RAISE WARNING` summary block now reports the aggregate count (lands in
    the PostgreSQL server log; goose clients do not forward server messages,
    so `pg_dist_partition` remains ground truth and T05 logs it per run).
  - Follow-up tracked: FK-inclusive sharding via composite-key redesign (new
    task; touches E07 ledger-core semantics and must not be smuggled into a
    migration). Reference-first reordering alone does not fix accounts/holds
    (their `ledgers` FK target is local).
