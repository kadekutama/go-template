**Last Updated:** 2026-09-16

## Objective

Serve cacheable reads from an async replica within a staleness bound, falling back to the primary when lag exceeds the bound, with lag metrics for E15 alerts.

## Scope

### In Scope

- `postgres/{replica,lag}.go`: replica pool handle, `replication_lag_seconds` gauge source, read/write selector (read-only E06 queries may use replica; all writes + decision reads use primary).
- Lag-bound fallback: lag beyond bound routes back to primary automatically.
- Metric + alert-rule shape reviewed against E15-T02 expectations.

### Out of Scope

- Replica server provisioning (compose/K8s manifests reference E17-T03/T04; this task owns the client side only).
- Cache invalidation (E08-T01); residency routing (E07-T08); RLS (E07-T02).

## Normative Inputs

- `tasks/epics/E07-persistence.md#E07-T07` for the backlog boundary.
- `docs/fintech-ledger-features.md §11.3` (async replica for DR), `§14` (active-active reads).
- `docs/ledger-core.md §7` (decision reads use the strong projection — never a lagging replica).
- `SPEC.md §12` (persistence/DR targets).

## Requirements

| ID | Requirement | Priority |

## Invariants and Failure Semantics

- Unknown/unreadable lag fails toward primary (safe direction), never toward a stale replica.
- Zero/negative bounds rejected at construction.
- Decision reads are statically primary (no per-call flag to get wrong).
