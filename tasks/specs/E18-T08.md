## Objective

Close the second-audit findings so ownership and commit binding match on whole
tokens rather than substrings, the verdict gate cannot be bypassed by rewriting
the Final Review Status section, and the handbook documents the validator test
suite and the acceptance semantics of a review report.

## Scope

### In Scope

- Anchor the `Owns:` authorization to whole-position path tokens so substring
  paths (e.g. `tasks/reviews/<ID>-extra.md`) do not authorize.
- Anchor the handoff Reviewed Commit binding to the `**Base / Head:**` line
  instead of any 40-hex string anywhere in the handoff.
- Make the completion gate check the Verdict family against the Final Review
  Status so a PASS final status cannot complete a task whose Verdict is
  REVISION REQUIRED or BLOCKED, with or without a resolution note.
- Define in SDD §3.4 when a required report is "accepted" (verdict plus
  resolution-note semantics) and document `test_check_tasks.py` in README.
- Add validator unit tests for each precision fix and keep all prior
  scenarios passing.

### Out of Scope

- Retroactive edits to released E18-T06/T07 artifacts; they stay frozen.
- SDD §6 "accepted" usage for API artifacts (different, pre-existing meaning).
- Frontmatter/permission design for `.opencode/agents/reviewer.md` (separate
  future task; the prompt body is not in this task's change surface).
- Any implementation (non-test Go), migration, contract, or E09 change.
