## Objective

Freeze the dual-broker topology: Redpanda v26.2 durable log topics + NATS Core v2.14.6 edge subjects with consumer-group/DLQ policy, backing `EventPublisher`/`EventConsumer`/`NotificationPublisher` ports.

## Scope

### In Scope

- `internal/infrastructure/messaging/redpanda/topics.go`: topic registry (`ledger.events.v1`, `outbox.facts.v1`, `webhook.jobs.v1`, `audit.streams.v1`), partition key `tenant_id:account_id`, retention/DLQ policy data.
- `internal/infrastructure/messaging/redpanda/client.go`: connection config (TLS + SASL/SCRAM options, dry-run without broker for topology tests); `producer.go`: the franz-go `Producer` implementing the `Broker` seam (sync produce, SASL plain/scram, flush-on-close) with `Module()` for fx lifecycle.
- `internal/infrastructure/messaging/nats/publisher.go` + `subjects.go`: NATS Core publisher (validates AND dials in the constructor — NATS is critical, so fail fast; no lazy Connect, no connection mutex) + `ledger.{tenant}.{event_type}` subject builders (via E05-T03), queue-group/DLQ naming.
- `deployments/redpanda/` + `deployments/nats/` compose fragments.
- `check-tasks.py --subjects` stays green.

### Out of Scope

- Publisher/consumer data plane (E08-T04), webhook delivery (E08-T05), actual broker operations in prod (E17), worker groups (E14).

## Requirements

### Resolved precedence conflict: `NotificationPublisher`

The epic and ADR-014/SPEC mention a `NotificationPublisher` port; the approved
E06-T12 contract set defines `EventPublisher`, `MessageConsumer`, `Notifier`,
and `WebhookDispatcher` instead — no `NotificationPublisher` exists. Per
`tasks/SDD.md §1`, the port owner (E06-T12) wins, so E08 does not invent a port
inside `internal/application/**` (outside its change surface). Corrected
2026-09-22 audit: the epic line claiming to implement `NotificationPublisher`
is struck — nothing here implements or requires it. The real-time edge is
consumed through `nats.Publisher` (`PublishEvent` subject bridge); the first
real consumer (E11 WebSocket bridge) must add the port through an E06 packet
amendment or reuse `Notifier`. Recorded here so the divergence is not
silently carried.

## Invariants and Failure Semantics

- Topology is data: no I/O in registry/builders; clients own dials with ctx deadlines.
- Partition key preserves per-account FIFO; cross-tenant aggregation never assumes order.
- Poison handling is policy (name + max delivers); E08-T04 enforces redelivery→DLQ.
