## Findings

### CR-001 — `forbidigo` Pattern Fails to Match Constructor `lo.NewTransaction` [Medium] [Confirmed]
- **Location:** `.golangci.yml:141` — `forbidigo.forbid`
- **Issue:** The `forbidigo` pattern bans `^lo\.(Transaction|ChannelDispatcher|Buffer|BufferWithContext|BufferWithTimeout|FanIn|FanOut)$`. In `github.com/samber/lo` (`retry.go:255`), the constructor for `Transaction` is `lo.NewTransaction[T]()`:
  ```go
  func NewTransaction[T any]() *Transaction[T]
  ```
  Calling `tx := lo.NewTransaction[int]()` does not match `^lo\.Transaction` and is permitted by `golangci-lint`.
- **Why it matters:** An engineer can instantiate `lo.NewTransaction[int]().Then(...).Process(state)`, adopting `lo`'s unapproved saga/transaction runner rather than `internal/application/workflow` and `internal/infrastructure/resilience`, defeating requirement E09.2-T01-R03 and ADR-026 Decision 2.
- **Evidence:** Inspection of `~/go/pkg/mod/github.com/samber/lo@v1.53.0/retry.go:255-262` confirms constructor name is `NewTransaction`. Pattern `^lo\.(Transaction|...)` matches the struct type `Transaction`, not the function call `NewTransaction`.
- **Plan violation:** Requirement `E09.2-T01-R03` ("`.golangci.yml` `forbidigo` MUST ban `lo.Attempt*`, `lo.Async*`, `lo.Transaction*`...").
- **Expected behavior:** All transaction constructors and methods in `lo` must be banned by `forbidigo`.
- **Recommended fix:** Update the pattern to ban both `NewTransaction` and `Transaction`:
  ```yaml
  - pattern: '^lo\.(NewTransaction|Transaction|ChannelDispatcher|Buffer|BufferWithContext|BufferWithTimeout|FanIn|FanOut)$'
  ```
- **Verification:** Create a temporary test call `_ = lo.NewTransaction[int]()` and verify `golangci-lint run` rejects it.

### CR-002 — Goroutine-Spawning Channel Helpers (`lo.SliceToChannel`, `lo.Generator`, `it.SeqToChannel*`) Omitted from Linter Bans [Medium] [Confirmed]
- **Location:** `.golangci.yml:141` — `forbidigo.forbid`
- **Issue:** In `github.com/samber/lo` (`channel.go:161-173, 191-204`), `SliceToChannel` and `Generator` spawn unmanaged background goroutines:
  ```go
  func SliceToChannel[T any](bufferSize int, collection []T) <-chan T {
      ch := make(chan T, bufferSize)
      go func() {
          for i := range collection { ch <- collection[i] }
          close(ch)
      }()
      return ch
  }
  ```
  Similarly, `github.com/samber/lo/it` (`it/channel.go:13-24, 29-41`) defines `SeqToChannel` and `SeqToChannel2` which execute `go func() { ... }()`. Neither `SliceToChannel` nor `Generator` are banned in `forbidigo`, and `github.com/samber/lo/it` is not denied in `depguard`.
- **Why it matters:** ADR-026 and repository concurrency rules require that all asynchronous goroutines use `internal/shared/kernel/safe` panic containment or `golang.org/x/sync/errgroup` with explicit cancellation contexts. Allowing `lo.SliceToChannel`, `lo.Generator`, or `it.SeqToChannel` permits raw, uncancellable goroutine spawns in production code, introducing goroutine leak and unhandled panic risks.
- **Evidence:** Code inspection of `~/go/pkg/mod/github.com/samber/lo@v1.53.0/channel.go:164, 194` and `it/channel.go:16, 32`. `.golangci.yml:141` lists `(Transaction|ChannelDispatcher|Buffer|BufferWithContext|BufferWithTimeout|FanIn|FanOut)` but omits `SliceToChannel`, `ChannelToSlice`, and `Generator`.
- **Plan violation:** ADR-026 Decision 2, Invariants & Failure Semantics ("`github.com/samber/lo/parallel` is forbidden across all packages; all goroutines must use `internal/shared/kernel/safe` or `golang.org/x/sync/errgroup`").
- **Expected behavior:** Channel helpers that spawn goroutines or block on channels must be banned via `forbidigo`, and `github.com/samber/lo/it` should be denied in `depguard`.
- **Recommended fix:**
  1. Add `SliceToChannel`, `ChannelToSlice`, and `Generator` to the `forbidigo` channel ban list.
  2. Deny `github.com/samber/lo/it` in `depguard` rules alongside `lo/parallel` and `lo/mutable` (or ensure `lo/it` channel helpers are banned).
- **Verification:** Verify with a temporary test file calling `lo.SliceToChannel(0, []int{})` and ensure `golangci-lint run` rejects it.

### CR-003 — `forbidigo` Pattern Vulnerable to Package Aliasing and Dot-Imports [Low] [Confirmed]
- **Location:** `.golangci.yml:139-144` — `forbidigo.forbid`
- **Issue:** All `forbidigo` patterns anchor strictly on the identifier `^lo\.`:
  - `^lo\.(Attempt|...)`
  - `^lo\.(Transaction|...)`
  - `^lo\.(Must|...)`
  When an import is aliased (e.g. `import mylo "github.com/samber/lo"`), expressions like `mylo.Attempt(...)` or dot-imported `Attempt(...)` will not match `^lo\.` and bypass the check.
- **Why it matters:** Code using non-standard import aliases or dot-imports can bypass all ADR-026 linter guardrails unnoticed.
- **Evidence:** `.golangci.yml:139-144`.
- **Plan violation:** None identified.
- **Expected behavior:** Patterns should match either the qualified package path `github.com/samber/lo.` or the package identifier `lo.`.
- **Recommended fix:** Update the patterns to support qualified package prefixes:
  `pattern: '^(github\.com/samber/lo\.|lo\.)(Attempt|...)'`
- **Verification:** Write a test probe with `import customlo "github.com/samber/lo"` and verify `golangci-lint` catches `customlo.Attempt(...)`.

### CR-004 — Inefficient $O(N \times K)$ Linear Scan in `DeriveTenantAlias` Candidate Generation [Low] [Confirmed]
- **Location:** `internal/domain/service/tenant_onboarding.go:60-69` — `DeriveTenantAlias`
- **Issue:** The original implementation constructed a lookup set `occupied := make(map[string]bool, len(taken))` once, allowing $O(1)$ collision checks for the candidate loop `for attempt := 2; attempt <= 100; attempt++`. The refactored code replaced this with `slices.Contains(taken, candidate)`, which executes an $O(N)$ linear scan of `taken` on every iteration, resulting in up to 99 linear scans ($O(99 \times N)$).
- **Why it matters:** While $N$ (existing aliases) is typically small, replacing a single $O(N)$ hash set construction with repeated slice scans within a 100-iteration loop is an asymptotic regression in algorithmic complexity.
- **Evidence:** `internal/domain/service/tenant_onboarding.go:64-69`.
- **Plan violation:** None identified.
- **Expected behavior:** Keep pre-indexed set lookup when querying candidate keys repeatedly against a collection.
- **Recommended fix:** Retain the pre-indexed `map[string]struct{}` lookup or use `lo.KeyBy` when performing repeated existence checks inside loops.
- **Verification:** Code inspection.
