## Objective

Cover the reporting surface beyond the 10 named types: reconciliation reports, scheduled report delivery, and bounded dashboard aggregations — without duplicating E06-T05's regulatory export (reused and extended in validation only).

## Scope

### In Scope

- `internal/application/command/extended_reports.go`: report `SubscriptionService` (subscribe/unsubscribe/due/deliver via the T05 `ReportService`) + consumer-owned `SubscriptionStore` (E07-T10 implements).
- `internal/application/query/{recon_reports,regulatory,dashboard}.go`: run summaries + status-filtered break lists, export reads + supported-types, bounded volume/status aggregations.
- `internal/application/dto/extended_reports.go`: edge shapes.
- Additive `ReconStore.ListBreaksByRun` (needed for run summaries; T05 fakes extended, no behavior change).
- Tests: recon summaries, all-4 regulatory types validated through the T05 service, scheduled delivery fires, aggregations paginate/bound.

### Out of Scope

- The 10 named report types (E06-T05), regulatory single-type rendering (E06-T05 `ExportRegulatoryReport` — reused, not re-implemented), cron scheduling itself (E14 drives `DueSubscriptions`/`DeliverSubscription`), persistence schema (E07-T10).

## Invariants and Failure Semantics

- Subscriptions never execute inside the subscribe call; delivery is a separate idempotent command per run key.
- Aggregation caps pages scanned; over-cap fails `DASHBOARD_TOO_LARGE` instead of scanning forever.
- Unknown commit outcomes resolve via identical resubmission, never blind retry.
