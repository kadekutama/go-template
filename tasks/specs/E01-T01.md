## Objective

Pin every SPEC §2 Go-module dependency at its reproducible target version so all
later code compiles against one verified set, eliminating "works on my machine"
version drift from day one.

## Interfaces and Data

No code interfaces change. The interface is the module graph itself: `go.mod`
(sealed versions) + `go.sum` (hashes) + `internal/shared/deps/deps.go` (retention
anchor). Later epics replace blank imports with real usage and may delete the
anchor once `go mod tidy` retains pins through production imports.

## Invariants and Failure Semantics

- Reproducibility: `go.mod`/`go.sum` MUST be committed together; CI's
  `go mod tidy -diff` gate MUST stay green.
- No `replace` or `exclude` directives to force SPEC versions against MVS —
  conflicts resolve upward and are recorded, never forced downward. In
  particular, never use plain `go get X@lower` to hold a pin: it silently
  downgrades other modules (observed 2026-09-14: `go get grpc@v1.69.0`
  downgraded migrate v4.19.1 → v4.17.1).
- No downgrade below a SPEC pin without an ADR; upgrades forced by MVS need only
  this packet's evidence record per `SPEC.md §2`.
- Toolchain stays Go 1.27.1 (`go` directive unchanged).

## Change Surface

**Owns:** `go.mod`, `go.sum`, `internal/shared/deps/deps.go` (new anchor package).  
**Coordinates:** `.github/workflows/ci.yml` (verify-only; tidy gate already exists via E00-T05).
