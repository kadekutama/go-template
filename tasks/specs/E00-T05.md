# Task Specification: E00-T05 — Minimal CI Gate + Dependency Automation

**Last Updated:** 2026-09-13

## Objective

Gate every PR on lint+build from the first code change, and keep the SPEC §2
target pins reviewable via weekly dependency automation.

## Scope

### In Scope

- `.github/workflows/ci.yml` (lint + build jobs only, fail-fast, with an
  "E17 extends this file" header — no second pipeline).
- `renovate.json` (weekly, grouped non-major updates, no auto-merge yet) and
  `.github/dependabot.yml` (weekly Go updates).

### Out of Scope

- Full CI matrix, staging deploys, image publishes (E17 extends `ci.yml`).
- Resolving live CI results (observable by the owner at the repo Actions page;
  recorded as residual until the first post-push run).

## Normative Inputs

- `tasks/epics/E00-foundation.md#E00-T05` for job/config requirements.
- `SPEC.md §11.1` (pipeline stages) and `SPEC.md §2` (target pins).
- `tasks/SDD.md` for evidence and completion rules.

## Requirements

| ID | Requirement | Priority |
|----|-------------|----------|
| E00-T05-R01 | `ci.yml` MUST trigger on PRs, run `go mod verify`, `go mod tidy -diff` equivalent, `make lint`, then `make build-all`, fail-fast. | must |
| E00-T05-R02 | CI MUST fail on unverified or non-tidy module files. | must |
| E00-T05-R03 | `renovate.json` MUST schedule weekly, group non-major updates, and disable auto-merge; `dependabot.yml` MUST schedule weekly Go-module updates. | must |
| E00-T05-R04 | No duplicate pipeline files may exist; the `ci.yml` header MUST document that E17 extends this file. | must |
| E00-T05-R05 | Checkout MUST use full history (`fetch-depth: 0`) so version derivation sees tags and commit counts; a `Resolve version` step MUST compute `VERSION` via `scripts/build/version.sh`, fail the job when it resolves to `dev`, and surface it in the job summary. `make build-all` then stamps every binary. | must |

## Executable Scenarios

| ID | Given | When | Then |
|----|-------|------|------|
| E00-T05-S01 | A PR is opened | CI runs | lint+build report status (live run observable post-push; structural proof here). |
| E00-T05-S02 | Untidy/unverified module files | CI runs | Job fails at the verify/tidy step. |
| E00-T05-S03 | The three config files | They are parsed + inspected | Valid YAML/JSON, schedules weekly, no auto-merge, single workflow file. |
| E00-T05-S04 | Any CI run | Checkout + version step execute | Full history present; `VERSION` non-`dev` and echoed to the summary. |

## Interfaces and Data

CI configuration is the interface: job names `lint` and `build` are the
status checks branch protection can require. No code interfaces change.

## Invariants and Failure Semantics

- Jobs fail fast; later steps never run after an earlier failure.
- Pinned toolchain (`go-version` from the SPEC §2 pin) so CI matches `go.mod`.
- No secrets in workflow files.

## Change Surface

**Owns:** `.github/workflows/ci.yml` (replaces that dir's `.gitkeep`),
`renovate.json`, `.github/dependabot.yml`.  
**Coordinates:** `Makefile` targets invoked by CI (no change), E17 (extends `ci.yml`).  
**Must Not Touch:** Go sources, task statuses other than E00-T05, Git remotes.
