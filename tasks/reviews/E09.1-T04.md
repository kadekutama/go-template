  ### CR-001 — NUL-bearing key fields alias distinct scopes into one in-flight result [Medium] [Confirmed]
  - **Location:** `internal/infrastructure/cache/coalesce/singleflight.go:74-76` —
    `CoalesceKey.inFlightKey` (validation gap at `singleflight.go:63-71` —
    `CoalesceKey.Validate`)
  - **Issue:** `Validate` checks only non-empty fields and the closed `Kind` enum.
    The in-flight key joins the four components with `"\x00"` separators, so two
    *different* (Provider, Scope) pairs compose byte-identical strings when a
    component contains NUL — e.g. Kind=fx_rate, digest=d: Provider `"a\x00b"` +
    Scope `"s"` and Provider `"a"` + Scope `"b\x00s"` both flatten to
    `fx_rate\x00a\x00b\x00s\x00d`. `singleflight` then shares one in-flight
    result across two logically distinct scope keys.
  - **Why it matters:** Violates the packet invariant "credentials or responses
    MUST NOT be shared across scopes" and R06's unconditional "different provider
    or tenant/authorization scope MUST NOT share an in-flight result" — worst case
    a cross-scope FX payload is served under the wrong authorization scope once
    E10-T02 wires production keys. E05's own key-segment rules
    (`internal/domain/service/isolation.go:22-39`) reject control characters; the
    coalescer omits that class entirely.
  - **Evidence:** `singleflight.go:73-76` builds the collision-prone string and
    `DoChan(key, …)` shares result channels by that exact string
    (`singleflight.go:145-149`). The alias is deterministic and reachable through
    the production `Do` path (no caller restriction exists; E10 consumer not yet
    wired).
  - **Plan violation:** E09.1-T04-R06 / S06; packet invariant on scope separation.
  - **Expected behavior:** Control characters (including `U+0000`) in any of
    Provider/Scope/RequestDigest are rejected with the existing typed
    `CodeInvalidKey`/`CodeInvalidKind` errors before `fn` runs, mirroring E05
    segment rules and preventing any alias.
  - **Recommended fix:** Smallest fix — extend `CoalesceKey.Validate` to reject
    control characters in the three string components (e.g. reject
    `r < 0x20 || r == 0x7f`, or `unicode.IsControl`); add two table cases to
    `TestCoalescerValidation` ("NUL in scope rejected", "NUL in provider
    rejected") asserting typed rejection before `fn`, plus one positive case
    asserting `("a", "b")` and `("a\x00b", "s")` never share (second is now
    rejected). No behavioral change for canonical keys.
  - **Verification:** `go test ./internal/infrastructure/cache/coalesce/... -count=3`
    and `go test -race ./internal/infrastructure/cache/... -count=1`; then the
    integration slice `go test -race ./test/integration/scheduler-egress/... -count=3`
    and `make lint`.
